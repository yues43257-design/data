# 策略 B 实验报告：大尺度混合电路的"保守 / 激进"决策

> 日期：2026-10-13 ｜ 代码：`mixed_stress.py`、`train_variant_policy_rl.py`、`hprob_sweep.py`
> 所有数字均为本仓库实测，可按下文"复现命令"重跑。

---

## 0. TL;DR（可直接引用的结论）

1. **一次性（one-shot）阈值掩码在深电路上必然失败**，不是训练不足——它省下的 T 门数 3–5 倍于合法值，但 **10/10 条电路都不安全**；纯回退后净收益为 **0**。
2. **一步修复（repair）就把这个 0 变成正收益**：从最不自信的降级开始逐个丢弃直到安全，深电路平均省 **21.0 T**，且**部署掩码恒安全**（零重训）。
3. **奖励尺度是按深度"条件化"的前提**：把 reward 的分母从绝对 T 数改为**合法余量**后，深窄课程不再塌成"什么都别降"，深电路一次性收益 **0.8 → 4.1 T（5.1×）**、浅电路 **13.5 → 39.25 T（2.9×）**。
4. **验证器在环的贪心是鲁棒的、但非严格最优**：上面所有训练配置变化下，贪心节省**完全不变**（深 6.0 T / 浅 66.25 T）。在 **500 条随机可枚举电路**上（§5.2）它**聚合捕获 98.4% / 逐点 96.4%** 的 oracle 节省——近似最优，但**不是**精确最优；根因是安全约束**非单调**（详见 §5.2）。
5. **深度条件化上限（§4）已实测**：它换来了深电路原始掩码 0%→100% 安全、浅电路 +5.8% 收益，但深电路省 T 比"阈值+修复"低 37%，**没有**达到"既要又要"——贪心仍是收益最优。
6. **真实电路 SOTA 对比（§6）**：在相对相位改写被认证合法的前提下，T-count 比 **TODD 少 24–33%**、比 Qiskit 默认优化器少 33–37%，且**把 TODD 叠加到我们的结果上无任何收益**；但在含 Hadamard 的电路（Grover）上改写非法，收益为零。
7. **真正的天花板不是算法而是物理**：层间 Hadamard 密度从 0 升到 0.1，合法安全余量就从 **100% 塌到 ~5%**（见 §5.3）。
8. **超越验证器规模（§7）已实测**：在 **24/32/50/100 数据比特**上归约验证器需要 `2^N` 稠密算符（100q = 2.3e46 PB，**OOM**），而 `support_tracker` 全程 **~40 ms** 完成安全认证；h=0 时 one-shot 100% 安全，h≥0.1 时 raw one-shot **100% 非法**、必须由 Tracker 修复成 ~21 T 的下界收益。
9. **排序消融（§8）：无预算时 NN 排序增益 = 0.00 T**（四种排序的贪心掩码 499/500 完全相同）；唯一的干净胜场是**精确验证器 + 受限查询预算 B∈{3,5,10}**（+5~+13 T）；换成 Tracker 后 NN 排序**大输**给零成本的 reverse-index（B≤5 时 NN 只有 0.00 T）。

## 1. 评测口径

| 项 | 说明 |
|---|---|
| 实例 | 混合控制数大电路：区块数 30–60，**每个区块的控制数独立取自 {2..8}** |
| 布局 | 所有区块共用一块数据寄存器（控制位 0..n_max−1、目标位 n_max），ancilla 池复用 |
| 安全性判据 | 相对相位替换后，数据寄存器 Z 基**测量分布**与全精确电路一致（TV ≤ 1e-9） |
| 验证器 | `mixed_stress.MixedVerifier`，工作在 `d = 2^(n_max+1)` 的归约空间，**无 2^k 枚举** |
| 策略 | ① 全精确（基线）② 全相对（合法上界，通常非法）③ **验证器贪心** ④ **一次性阈值** |

验证器正确性（与完整电路仿真逐 mask 比对）：**72/72（混合实例）+ 80/80（同构）+ 124/124（随机）掩码，0 处不符**。

## 2. 第一步：一次性掩码修复（repair）

### 2.1 问题

阈值决策只看每个区块的独立分数，忽略**累积**安全性。深电路里原始掩码会降级 4–13 个区块，只要其中一个破坏安全，旧实现就整条回退 → 收益归零。

### 2.2 方法

```
repair(mask): 按置信度从低到高逐个丢弃已接受的降级，直到判据通过
```

`mask = 0` 恒安全，因此必然终止，**返回值永远安全**。

### 2.3 实测（深电路，h_prob = 0.5，2 条 44/60 区块电路）

| 电路 | 原始阈值掩码 | 纯回退（旧） | **修复后（新）** | 验证器贪心 |
|---|---:|---:|---:|---:|
| #1（44 块） | 174 T（**非法**） | 0 T | **15 T** | — |
| #2（60 块） | 261 T（**非法**） | 0 T | **27 T** | — |
| **均值** | **217.5 T（非法）** | **0.0 T** | **21.0 T** | **55.5 T（100% 安全）** |

修复平均丢弃 9.5 个区块；100% 的电路都触发了修复。

**结论**：修复把"全灭"变成"永远有收益、永远安全"，成本为零（无重训），但它恢复的是贪心的一部分收益（21.0 / 55.5 ≈ 38%）。

## 3. 第二步：奖励尺度修正（legal-headroom normalization）

### 3.1 问题

原 reward：

```python
value = (t_all_exact - t_final) / t_all_exact
```

分母是**绝对 T 数**，于是"最好能省多少"被深度稀释：4 块电路最好能省 ~15%，40 块电路只有 ~0.3%。深电路在梯度里几乎无声，而 `risk_penalty = −0.5` 是固定值 → 策略唯一能学到的就是"**什么都别降**"。

### 3.2 方法

```python
self.headroom = t_all_exact - t_all_relative          # 合法余量（全相对能给的最大节省）
value = (t_all_exact - t_final) / max(self.headroom, 1)
```

深/浅实例的奖励量级因此可比（都落在 [0,1]），"深电路少降、浅电路多降"的**深度条件化**行为才第一次可学。

### 3.3 A/B 实测（同 seed / 15 epoch / 同 held-out 池；只改 `--deep-fraction`）

| 指标 | 修前·基线 0.0 | 修前·课程 0.6 | **修后·基线 0.0** | **修后·课程 0.6** |
|---|---:|---:|---:|---:|
| 深电路·原始阈值安全率 | 0% | **100%** | 0% | **100%** |
| 深电路·一次性+修复 省 T | 6.0 | **0.8** | 5.6 | **4.1** |
| 深电路·贪心 省 T | 6.0 | 6.0 | 6.0 | 6.0 |
| 浅电路·一次性 省 T | 63.0 | **13.5** | 63.0 | **39.25** |
| 浅电路·贪心 省 T | 66.25 | 66.25 | 66.25 | 66.25 |

（深电路 = 8 条 held-out，nc=2、30–50 块；浅电路 = 12 条 held-out，2–7 块。）

**修正带来的提升（课程档）**：深电路一次性 **0.8 → 4.1 T（5.1×）**；浅电路 **13.5 → 39.25 T（2.9×）**，同时保住"深电路原始掩码 100% 安全"这一课程目标（修复丢弃数 8.0 → 0.0）。

### 3.4 诚实的边界

- 课程仍**用浅电路收益换深电路原始安全性**（63 → 39 T，−38%）。这是"单一标量阈值"的固有取舍。
- 该收益属于**健壮性**（少做修复），**不是**更多 T 门节省——纯修复已拿到贪心的 93%（5.6 / 6.0 T）。
- 因净收益为健壮性而非节省，`--deep-fraction` **默认 0.0（opt-in）**。

## 4. 第三步：深度条件化阈值（**已实现并实测**）

### 4.1 方法

先验证了"提高阈值"这条路——**无效**：深电路即使把阈值推到 τ=0.99，模型仍保留 6.6 个区块，原始掩码安全率只有 12%（模型排序好但**标定差**，抬阈值几乎不减少数量）。所以必须按**数量**而非概率做深度条件化：

```
k_max(blocks) = clamp(round(4 / sqrt(blocks)), 1, blocks)      # 浅电路 2–3 个，深电路 1 个
mask = 按分数取 top-k_max  →  验证器确认 / 修复兜底
```

实现：`mixed_stress.depth_budget()` + `top_mask()`，并在战报里与"阈值+修复"并列输出（`--num-tests` 任意）。

### 4.2 消融（held-out：16 条浅 + 12 条深，同一策略权重、同一判据）

| 指标 | 浅电路（n=16） | 深电路（n=12） |
|---|---:|---:|
| 原始阈值掩码 安全率 | 100% | **0%** |
| 深度上限掩码 安全率 | 100% | **100%** |
| 阈值 原始省 T | 43.3 | 24.8（**非法**） |
| 阈值 + 修复 省 T | 43.3 | **4.8** |
| **深度上限 + 修复 省 T** | **45.8** | 3.0 |
| 验证器贪心 省 T | **51.4** | **8.2** |

### 4.3 结论：**"既要又要"没有达成**

| 判据 | 目标 | 结果 | 达成 |
|---|---|---|---|
| 深电路原始阈值安全率 | ≥ 90% | **100%** | ✅ |
| 深电路一次性+修复 省 T | ≥ 5.0 | **3.0** | ❌ |
| 浅电路一次性 省 T | 相对优于基线 | 43.3 → **45.8（+5.8%）** | ✅ |
| 贪心省 T | 不变 | 8.2 / 51.4（与基线一致） | ✅ |

- **收获**：深度上限换来**原始掩码安全**（深 0% → 100%，零修复）与浅电路小幅增益（+5.8%）。
- **代价**：深电路省 T 比"阈值+修复"低 **37%**（3.0 vs 4.8），且两者都远低于贪心（8.2）。
- **原因**：固定上限无法复刻贪心"按置信度顺序逐个加、安全才留"的**序贯**逻辑；且当分数大量并列时 top-m 的选取不稳定——实测 **top-2 经修复后常退化为 0**（并列时"丢弃最不自信"丢掉的是另一个 bit，剩余集合 ≠ top-1）。

**部署建议**：默认继续用 **`阈值 + 修复`**（深电路更省）；只有当你需要"**零验证器调用的安全掩码**"时才用深度上限。贪心仍是收益最优。

### 5.2 贪心最优性（500 条随机电路的大样本实测）

**早期小样本（3 条手工可枚举实例）**：

| 电路 | oracle 节省 | 贪心节省 | 捕获率 |
|---|---:|---:|---:|
| 6 块 [8,6,6,8,6,7] | 72 T | 72 T | 100% |
| 8 块 [3,2,4,3,8,8,2,5] | 33 T | 33 T | 100% |
| 10 块 [2,7,2,5,7,4,4,3,7,3] | 12 T | 12 T | 100% |

据此写下的"贪心达到 oracle 的 100%"是**小样本**结论；下面的大样本把它修正掉。

**大样本（`oracle_vs_greedy.py`，500 条随机混合电路，5–12 块，控制数 ∈ {2..6}，h_prob = 0.7，逐条 2^k 全枚举求 oracle，seed 20261014）**：

| 指标 | 数值 |
|---|---:|
| 完全最优（y = x）实例 | **482 / 500 = 96.4%** |
| **聚合捕获率（Σ贪心 / Σoracle）** | **98.37%** |
| 单实例捕获率（均值 / 中位） | 98.7% / 100% |
| 平均缺口 | 0.558 T（中位 0，最差 60 T） |
| 回归 y = a·x + b（R² / 对 y=x 线 R²） | a = 0.930，b = 1.836（0.932 / 0.925） |

产物：散点图 `reports/figures/fig4_oracle_vs_greedy.{png,pdf}`、捕获率分布直方图 `reports/figures/fig4b_capture_histogram.{png,pdf}`、逐电路数据 `reports/figure_data/oracle_vs_greedy.json`。

图 `fig4b` 展示**逐电路捕获率**的分布形状：482/500 条死死钉在 **100 %**，其余 18 条散落在 37.5 %–90.9 % 的长尾上（平均 99.0 %，中位 100 %）——即"绝大多数完美、极少数塌陷"，这正是聚合 98.4 % 与逐点 96.4 % 两个数字同时成立的原因。

**结论修正**：贪心**不是**逐点最优，而是**聚合意义上 98.4%、逐点 96.4% 地逼近上限**。约 4% 的实例会少降级，最差一条只拿到 oracle 的 37.5%（60 T）。

**根因（`deviation_table` 与逐 mask 直接 `deviation()` 双重验证，逐位一致）**：安全约束**非单调**。
以 7 块、控制数 [5,3,3,6,5,5,4] 为例：mask {0,1,6} 的偏差 = 0.500（**不安全**），{0,1,2,6} 偏差 = 1.4e-14（**安全**），{0,1,2,4,6} 又回到 0.500。即"再多加一个区块反而重新变安全"。
因此任何**被拒就永不回看**的贪心都到不了那些**必须经过不安全中间态**才能抵达的最优点。已实测：多轮 multipass、1-swap 局部搜索、以及**只走安全中间态**的 beam(64/256/1024) 均**未**把 96.4% 抬高（beam 逐点还常更差，因为按 t_count 剪枝会丢掉最优组合）。

**实践含义**：k ≤ ~20 时（2^k 可枚举）直接跑穷举 oracle 即得 100%；在 k = 30–60 的大电路上，贪心以 ~98% 的聚合捕获率、O(k) 次验证器调用在线运行——这正是它被部署的原因。

### 5.3 物理天花板：H 门密度决定一切

h_prob 扫描（10 条混合电路/档，seed 20261012，同一批电路形状）：

| h_prob | All-Exact T | 贪心省 T | 贪心捕获率 | 全相对安全率 | 一次性省 T（旧·纯回退） |
|---:|---:|---:|---:|---:|---:|
| 0.00 | 2221.8 | **952.2** | **100.0%** | 100% | 325.2 |
| 0.10 | 2221.8 | 59.1 | 6.2% | 0% | 0.0 |
| 0.30 | 2221.8 | 54.9 | 5.8% | 0% | 0.0 |
| 0.50 | 2221.8 | 47.4 | 5.0% | 0% | 0.0 |
| 0.80 | 2221.8 | 50.4 | 5.3% | 0% | 0.0 |

**只要下游存在 Hadamard，修正就不再保持对角 → 合法余量从 100% 塌到 ~5%。** 这是电路结构问题，不是验证器或策略问题。

### 5.4 为什么"保守判据"（Pauli/支撑集追踪）不划算

同一批深电路上，把**精确判据**换成**保守判据（Ω 必须严格对角）**：

| 电路 | 精确贪心 | 保守贪心 | 损失 |
|---|---:|---:|---:|
| 36 块 | 30 T | 15 T | **50%** |
| 39 块 | 66 T | 27 T | **59%** |
| 38 块 | 36 T | 21 T | **42%** |
| h_prob=0 时 | 588/978/714 T | 同左 | 0% |

归约验证器对**深度**是多项式、对**宽度**才是指数；当前数据宽度只有 9 个数据比特，所以换保守验证器**既不会更快、还会损失约一半余量**。

**支撑集/对角性追踪器（`support_tracker.py`）的直接实测**（O(gates) 时间、O(qubits) 空间）：

| 池 | 精确贪心 | 追踪器贪心 | 损失 | 不安全性 |
|---|---:|---:|---:|---:|
| 浅电路 n=16 | 51.4 T | 22.9 T | **55.5%** | 0 |
| 深电路 n=12 | 8.2 T | 3.0 T | **63.6%** | 0 |

- **可靠性**：对 152 个 mask 逐一与精确验证器比对，**0 次把不安全掩码判为安全**（这正是它存在的理由）。
- **保守性**：它在 mask 级别只接受 **8%** 的掩码；在可部署的贪心里损失 **55.5%（浅）/ 63.6%（深）**——比 §5.4 上半部分用矩阵判据估的 42–59% **更差**（追踪器比矩阵"Ω 对角"更保守）。
- **可扩展性**：单次判定 0.04–0.08 ms，50 区块的完整贪心 2.6–5.0 ms，与宽度无关、只随门数线性增长。

## 6. 真实电路 SOTA 对比

> 数据源：`reports/figure_data/realworld_sota.json`（由 `realworld_benchmark.py --json` 直接生成，非手抄）。
> 复现：`.venv/bin/python realworld_benchmark.py --size-map "mcx:3,4,5;adder:3,4,8,16,32;grover:3" --todd-timeout 60 --json reports/figure_data/realworld_sota.json`

这一节把编译器放进**外部基线**里：Grover、CDKM 加法器（3 → 32 bit，跨越 20 比特内存墙）、
以及本项目自己的 C^nX 阶梯，与 **Qiskit 默认优化器**和 **TODD（Heyfron & Campbell 2019）**正面对比。

### 6.1 对照设置

| 列 | 含义 |
|---|---|
| `L0` / `L3` | Qiskit 转译到 Clifford+T，`optimization_level` = 0 / 3（"默认优化器"基线） |
| `TODD` | **PyZX `phase_block_optimize`** —— Heyfron–Campbell TODD 的实现，按 Hadamard 分块施加；`--todd-timeout` 默认 60 s，超时记 `timeout` |
| `ours` | 本项目的相对相位改写：Toffoli → 4-T RCCX，纯 C^nX → 整块 RCCX 阶梯，**仅在注入的对角修正被认证存活时采用** |
| `TODD(ours)` | 在**我们的电路之上**再跑一遍 TODD —— 检验是否还有被我们漏掉的优化 |
| `best` | TODD / ours / TODD(ours) 中的最优值；**非法的相对相位改写不计入** |
| 认证方式 | `Exact Verifier`（≤ 11 qubits，构造 `2^N` 算符）或 `Support Tracker (OOM-free)`（> 11 qubits，`O(gates)` 对角性追踪） |

所有电路都要求可表示为 **Toffoli + Clifford**（否则 T-count 没有定义）。Qiskit 的
`MCXGate(n>=3)` ancilla-free 综合使用 π/8 旋转，**不属于 Clifford+T**，因此不进入本表
（Grover(n>=4) 因此被自动跳过）。

### 6.4 四条结论

1. **在改写被认证合法的电路上，我们比 TODD 少 24–33% 的 T 门。**
   C³X `17→12`（−29%）、C⁴X `27→20`（−26%）、C⁵X `37→28`（−24%）、
   加法器 3/4-bit `36→24`、`48→32`（各 −33%）。
   相对"每个 Toffoli 7 个 T"的朴素代价是 **−43%**；相对 Qiskit 默认优化器 L3 是 **−33…−37%**。
2. **把 TODD 叠加在我们的结果之上，一点也压不下去**：`TODD(ours) = ours` **全部 8 条合法电路成立**
   （含 8/16/32-bit 加法器）。这条堵住了"你只是没让最强工具再跑一遍"的反驳。
3. **优势来源是"更便宜的基元"，不是"更好的搜索"**：TODD 在相位多项式上做 GF(2) 消元，
   它并不知道 `RCCX = 4 T` 这个电路恒等式；我们赢在把一个 7-T 基元换成 4-T 基元。
4. **跨过 20 比特内存墙后，可比性只在"我们这边"**（§6.5）：`ours` 保持 `4×Toffoli`（32-bit：256 T，
   相对 L3 −33%），而 TODD 在 34q / 66q 上 **60 s 超时**，我们的认证只需 **0.3 / 0.6 ms**。

### 6.5 跨越 20 比特内存墙：TODD 超时，我们 0.3 ms 认证

- **认证方式自动切换**：`≤ 11` qubits 用精确验证器（构造 `2^N` 算符，34q 就要 `2^34`，不可行）；
  超过即切换到 `support_tracker.py` 的**对角性追踪**（`O(gates)` 时间、`O(qubits)` 空间）。
  **交叉校验**：把同两个小加法器强制走 Tracker（`--exact-limit 0`），结论与精确验证器**完全一致**，
  耗时 `0.1 ms` vs `96 ms / 2363 ms`（约 1e3–2e4×）。运行：
  `.venv/bin/python realworld_benchmark.py --circuits adder --qubits 3,4 --exact-limit 0`
- **T-count 线性外推**：CDKM n-bit 加法器有 `2n` 个 Toffoli，`ours = 4·(2n) = 8n`，
  Qiskit L3 `= 6·(2n) = 12n` → 恒定 **−33%**；32-bit 实测 `384 → 256`，与公式一致。
- **TODD 的可扩展性**：PyZX 的 `phase_block_optimize` 在 16-bit（34q）与 32-bit（66q）上 60 s 未收敛；
  而在**我们已降级的电路上**再跑 TODD 只需 6.3 s / 45.7 s，且结果**等于 ours**（无额外收益）。

### 6.6 三条限制

1. **t-par 不是 T-count 基线，而且当前环境没有它的实现。**
   Amy–Maslov–Mosca 2014 的 t-par 优化的是 **T-depth**（用额外辅助比特换深度），
   **T-count 通常会变高**。所以本节的 T-count 对照用 TODD 是正确的；若要给出 T-depth 结论，
   需要一个 t-par 实现（`pytket` / `tweedledum` 均未安装，PyZX 也没有）。
   这是本报告**尚未覆盖**的一块，不应含糊带过。
2. **34q/66q 的 "timeout" 是 PyZX 实现的墙钟现象，不是"TODD 做不到"的定论。**
   换更快的实现 / 更长的预算可能压出更低的 T-count；论文里应写"60 s 预算内未返回"，
   不能写成"TODD 无法处理"。同时 `ours` 在 34q/66q 上仍只是**下界**（Tracker 是充分判据）。
3. **结果仍是"子电路级"的。** 认证的是"该电路以 Z 基测量收尾"时对角修正无害；
   加法器与 MCX 阶梯都是**子程序**，嵌进下游还有 Hadamard 的更大算法时必须对**整条电路**重判 ——
   按 §5.3 的 H 断崖多半会失效，Grover 就是现成反例。TODD 版本为 PyZX 0.10.6。

## 7. 超越归约验证器规模：24–100 数据比特的实测

> 数据源 `reports/figure_data/wide_scale_stress.json`（`wide_scale_stress.py` 直接落盘，240 条电路）。
> 复现：`.venv/bin/python wide_scale_stress.py --widths 24,32,50,100 --h-probs 0.0,0.1,0.5 --circuits 20`

### 7.1 前提：这个尺度上不存在精确 oracle

归约验证器的判据是"Z 基测量分布一致"，需要 `2^N × 2^N` 稠密算符。实测所需内存：

| 宽度 N | 精确验证器所需算符内存 | 标注 |
|---:|---:|:--|
| 24 | 4.0 PB | **Verifier: OOM (2^N)** |
| 32 | 2.6e5 PB | **OOM (2^N)** |
| 50 | 1.8e16 PB | **OOM (2^N)** |
| 100 | 2.3e46 PB | **OOM (2^N)** |

唯一 sound 的可行判据是 `support_tracker.py` 的**对角性追踪**（`O(gates)` 时间、`O(qubits)` 空间）。它在两种布局上都逐掩码对 2^N 精确矩阵校验过：

- `support_tracker.py --self-test`（同构布局）：**152** 个掩码，tracker 接受但真实修正非对角 = **0**；
- `wide_scale_stress.py --self-test`（**wide 布局**，含 ancilla 路径与 h=0.1/0.3/0.7/1.0）：**144** 个掩码，unsound = **0**。

注意 tracker 是**充分**判据（接受 ⟹ 安全）；被拒的掩码未必真不安全，故下列节省都是**下界**。

### 7.2 设置

宽度 24/32/50/100 数据比特；每块保留原生控制数 C²X…C⁸X，随机落在宽寄存器窗口上；层间 Clifford 作用在**全部**数据比特。每 (宽度, h_prob) 20 条电路、块数 20–60，共 **240** 条；策略权重冻结（`variant_policy_rl_best.pt`）。

关于"把块的局部导线重映射到 `0..15`"：**不需要**。`_block_graph(n)` 是块的规范局部 ZX 图（索引局部于该块，0..n+1），`context_features` 不含全局宽度项，所以冻结模型对同一控制数的块，在任何宽度、任何位置给出**完全相同**的输入张量。

### 7.4 结论

1. **可行性（最硬的一条）**：在 **100 数据比特、~40 个区块**的电路上，"打分 → 追踪 → 修复"全程 **~40 ms** 跑完；同一电路上精确验证器需要 **2.3e46 PB**。这是"超越验证器规模仍能编译 + 安全认证"的直接证据，且耗时只随门数近似线性增长、与宽度无关。
2. **h=0（下游无 H）近乎全绿**：one-shot 100% 安全，省 406–660 T；greedy 省 793–922 T（≈ 全精确基线的 43%）。宽度 24→100 不改变正确性，只增加耗时。
3. **h≥0.1 时 one-shot 原始掩码 100% 非法**：它"省"221–724 T 全是假象（掩码本身不安全）；Tracker 修复必须丢弃 11–34 个块，仅剩 14–26 T。`Tracker Greedy` 略好（21–33 T）且同样廉价。
4. **H 断崖在尺度上依旧**：安全余量从 h=0 的 ~43% 基线塌到 h≥0.1 的 ~1%。瓶颈是 Hadamard，不是宽度、也不是验证器——与 §5.3 完全一致。
5. **Depth-Cap 在深电路上退化为 top-1**（`depth_budget(blocks≥16)=1`），故只省 ~21 T（h=0）/ 0 T（h>0），是四者里最差的。

### 7.5 诚实边界

- 这里的"安全"是 tracker 的**充分**判据（对角修正），**不是**精确判据；在这些宽度上无法与 oracle 对比（正因为 OOM），所以表里所有 T 节省都是**下界**。
- 本轮只回答"能否在超宽下安全编译并量化收益"，**不**证明 one-shot 本身变好——恰恰相反，raw one-shot 在此尺度上 100% 非法。
- 顺带修掉一个潜在 bug：`WideInstance` 在 `ancilla_pool < n-2` 时会静默漏映射一根导线（`KeyError`）；已加 `n ≤ ancilla_pool + 2` 的钳制。

## 8. 消融：贪心排序与验证预算（NN 到底赢在哪）

> 数据源 `reports/figure_data/ablation_ordering.json`（`ablation_ordering.py` 直接落盘）。
> 复现：`.venv/bin/python ablation_ordering.py --a1-circuits 500 --deep-circuits 20 --wide-circuits 20`

贪心解码器 `for b in ORDER: if safe(accepted|{b}): accepted|={b}` 的结果**完全由排序决定**。这里把"冻结策略排序"与三种**零成本**静态规则对比：

| 排序 | 含义 | 成本 |
|---|---|---|
| `policy` | 模型打分降序 | 一次前向 |
| `reverse_index` | `idx=K-1…0`（末端优先） | 免费 |
| `saving_desc` | 单块可省 T 降序（并列时从后往前） | 免费 |
| `random` | 随机打乱（5 次平均） | 免费 |

### 8.1 无预算：排序无关，NN 增益 = 0.00 T

| 场景 | policy | reverse_index | saving_desc | random | policy − 最佳静态 |
|---|---:|---:|---:|---:|---:|
| 精确验证器，500 条混合电路(5–12 块) | 33.70 | 33.70 | 33.70 | 33.70 | **+0.00** |
| 精确验证器，20 条深电路(30–50 块) | 24.60 | 24.60 | 24.60 | 24.60 | **+0.00** |
| Tracker，24q 深电路(h=0.1) | 35.55 | 35.55 | 35.55 | 35.55 | **+0.00** |
| Tracker，50q 深电路(h=0.5) | 21.15 | 21.15 | 21.15 | 21.15 | **+0.00** |

**掩码级复核**：500 条精确电路里，四种排序的贪心掩码 **499/500 完全相同**；唯一不同的一条（控制数 `[2,3,3,4,2]`）两个掩码的省 T **仍然相等**（差异块控制数相同）。

**结论**：验证预算充足时，神经网络排序相对零成本启发式的增益是 **0.00 T**。§5.2 里贪心距 oracle 的那 3.6% **不是排序问题**，而是"贪心只给极大解、不给最大解"的结构性缺口（beam/1-swap 也修不掉，见 §5.2）。

### 8.2 受限查询预算：排序才起作用，胜负随 oracle 翻转

预算 `B` = 每条电路最多调用验证器/Tracker B 次（只测排序最前的 B 个块）。

**精确验证器 —— NN 在这里真正胜出：**

| 场景 | B | policy | reverse_index | saving_desc | random | policy − 最佳静态 |
|---|---:|---:|---:|---:|---:|---:|
| A1 500 条(5–12 块) | 1 | 13.33 | 15.02 | 9.31 | 4.27 | −1.69 |
| A1 | 3 | 31.00 | 16.53 | 19.57 | 13.24 | **+11.42** |
| A1 | 5 | 32.30 | 19.35 | 27.15 | 21.80 | **+5.15** |
| A1 | 10 | 33.66 | 30.20 | 33.47 | 32.63 | +0.19 |
| A2 20 条(30–50 块) | 1 | 10.80 | 11.10 | 6.75 | 1.02 | −0.30 |
| A2 | 3 | 19.05 | 11.85 | 6.75 | 1.74 | **+7.20** |
| A2 | 5 | 24.45 | 11.85 | 6.75 | 2.88 | **+12.60** |
| A2 | 10 | 24.60 | 11.85 | 9.15 | 6.87 | **+12.75** |

**Tracker（宽寄存器）——NN 大输给零成本规则：**

| 场景 | B | policy | reverse_index | saving_desc | random | policy − 最佳静态 |
|---|---:|---:|---:|---:|---:|---:|
| 24q h=0.1 | 1 | 0.00 | 21.60 | 9.75 | 1.08 | **−21.60** |
| 24q h=0.1 | 5 | 0.00 | 35.55 | 16.65 | 5.40 | **−35.55** |
| 50q h=0.1 | 5 | 0.00 | 28.05 | 11.40 | 3.87 | **−28.05** |
| 50q h=0.5 | 5 | 0.00 | 21.15 | 9.45 | 2.58 | **−21.15** |
| 50q h=0.5 | 10 | 0.00 | 21.15 | 12.75 | 6.48 | **−21.15** |

### 8.3 为什么会翻转（关键解释）

1. **Tracker 的判据有乘积结构。** 它的规则（H 命中即"broken"、CNOT/块只做**并集**式支撑传播）意味着
   `safe(S) = ∧_{i∈S} survives(i)`，且 `survives(i)` 与掩码无关。于是：**无预算时任何顺序的贪心都收敛到同一个最大可行集 F**（也就是 Tracker 下的最优），排序完全无关；而**最后一个区块永远安全**（下游无 H），所以 `B=1` 时 `reverse_index` 直接拿走它的完整节省。**这条准则下，模型没有任何可做的。**
2. **模型是拿精确 oracle 的标签训的**（预测"该块是否属于精确最优掩码"），与 Tracker 的准则**不一致**。所以在 Tracker 下，模型把那些"精确可行但 Tracker 不可行"的块排到前面，B 很小时预算被全部浪费 → **0.00 T**。
3. **精确验证器是唯一让"学出来的排序"有价值的场景**：它的可行集非单调、且块间存在价值差异（控制数决定省 T），模型确实学到了一点"既可能安全、又值钱"的联合信息，故在 B=3–10 稳定胜出。

### 8.4 直接回答"NN 到底赢在哪"

- **唯一干净胜场**：**精确验证器 + 受限查询预算 B ∈ {3,5,10}**，比最强零成本静态规则多省 **5–13 T**（A1 `+5.2…+11.4`，A2 `+7.2…+12.8`）；B=1 时反而略输。
- **无预算**：**不赢**（0.00 T）——排序根本不影响结果。
- **换成 Tracker**：**惨败**（−10…−36 T）。部署 Tracker 时应**直接丢弃模型排序**，用 `reverse_index`，或干脆用一次 O(k·gates) 前向扫描直接算出可行集 F（**零次模型调用**即得 Tracker 下的最优）。

## 10. 局限与后续

1. **§4 的深度条件化上限仍未达到"既要又要"**（深电路省 T 比"阈值+修复"低 37%）。要再进一步，需要把上限做成**可学的序贯决策**（例如按置信度顺序逐个决定、每步看已提交状态），而不是预先固定的 top-k；但那本质上就是在逼近贪心。
2. **贪心不是严格最优（§5.2）**：500 条随机电路上聚合捕获 **98.4%**、逐点 **96.4%**，最差一条短 60 T。根因是安全约束**非单调**，"拒绝即不回看"的贪心存在结构性缺口；已实测的 multipass / 1-swap / beam 都补不上。要 100% 需 2^k 穷举（k ≲ 20 可行，更大的 k 不可行）——这是当前部署与理论上限之间唯一已知的、无法用同族启发式消除的差距。
3. 目前所有安全判据都是**全局测量统计**一致；未考虑噪声/近似保真度预算。
4. **T-depth / t-par 尚未覆盖**：§6 只做了 T-count；t-par 基线需要一个独立实现（见 §6.4 第 1 条）。
5. **"宽度"有两种含义，别混用**：在共享寄存器框架（`mixed_stress`）里所有块共用 `n_max+1` 个数据比特，验证器成本是 `2^(n_max+1)`（`n_max` = 最大控制数），舒适到 `n_max` ≈ 18；而在**真正宽寄存器**的电路里（§7，块落在不同导线上），成本是 `2^N`，12–19 比特以上就 **OOM**。
6. **最有潜力的"做大蛋糕"方向不是 ML 而是编译期 H 重排**：h_prob=0 时可拿到 100% 的合法上界（952 T），说明只要把 Hadamard 从目标区块的下游挪开，降级就能活。这需要 Clifford 重综合/对易来腾出 H-free 窗口。
7. **超宽实测只给下界（§7）**：24–100 比特上精确判据不存在（OOM），安全性只能由 `support_tracker` 的充分判据认证，故报告的 T 节省是**下界**；且 raw one-shot 在此尺度 100% 非法，收益全部来自 Tracker 修复/贪心。
8. **排序消融的边界（§8）**："无预算时排序无关"是**实测**结论（精确验证器 499/500 掩码相同、Tracker 侧有乘积结构支撑），并非对任意电路族的一般定理；受限预算下的胜负也只在这三类实例上测过，换分布（控制数/块数/H 位置）需重测。
