## 0. TL;DR（可直接引用的结论）

1. **一次性（one-shot）阈值掩码在深电路上必然失败**，不是训练不足——它省下的 T 门数 3–5 倍于合法值，但 **10/10 条电路都不安全**；纯回退后净收益为 **0**。
2. **一步修复（repair）就把这个 0 变成正收益**：从最不自信的降级开始逐个丢弃直到安全，深电路平均省 **21.0 T**，且**部署掩码恒安全**（零重训）。
3. **奖励尺度是按深度"条件化"的前提**：把 reward 的分母从绝对 T 数改为**合法余量**后，深窄课程不再塌成"什么都别降"，深电路一次性收益 **0.8 → 4.1 T（5.1×）**、浅电路 **13.5 → 39.25 T（2.9×）**。
4. **验证器在环的贪心是鲁棒的、但非严格最优**：上面所有训练配置变化下，贪心节省**完全不变**（深 6.0 T / 浅 66.25 T）。在 **500 条随机可枚举电路**上（§5.2）它**聚合捕获 98.4% / 逐点 96.4%** 的 oracle 节省——近似最优，但**不是**精确最优；根因是安全约束**非单调**（详见 §5.2）。
5. **深度条件化上限（§4）已实测**：它换来了深电路原始掩码 0%→100% 安全、浅电路 +5.8% 收益，但深电路省 T 比"阈值+修复"低 37%，**没有**达到"既要又要"——贪心仍是收益最优。
6. **真实电路 SOTA 对比（§6）**：在相对相位改写被认证合法的前提下，T-count 比 **TODD 少 24–33%**、比 Qiskit 默认优化器少 33–37%，且**把 TODD 叠加到我们的结果上无任何收益**；但在含 Hadamard 的电路（Grover）上改写非法，收益为零。 ⚠️ 主基线**已换成 pyZX `full_reduce`（FR）**（§6.8）：换完后**加法器上的 T-count 优势归零**（逐位相同），阶梯优势也只是**恒定 +3 T**、相对值随 n 衰减到 1%（§6.10）；与 FR 是 Pareto（我们赢 Clifford 门数与总深度，FR 赢 T-depth）。
7. **真正的天花板不是算法而是物理**：层间 Hadamard 密度从 0 升到 0.1，合法安全余量就从 **100% 塌到 ~5%**（见 §5.3）。
8. **超越验证器规模（§7）已实测**：在 **24/32/50/100 数据比特**上归约验证器需要 `2^N` 稠密算符（100q = 2.3e46 PB，**OOM**），而 `support_tracker` 全程 **~40 ms** 完成安全认证；h=0 时 one-shot 100% 安全，h≥0.1 时 raw one-shot **100% 非法**、必须由 Tracker 修复成 ~21 T 的下界收益。
9. **排序消融（§8）：无预算时 NN 排序增益 = 0.00 T**（四种排序的贪心掩码 499/500 完全相同）；唯一的干净胜场是**精确验证器 + 受限查询预算 B∈{3,5,10}**（+5~+13 T）；换成 Tracker 后 NN 排序**大输**给零成本的 reverse-index（B≤5 时 NN 只有 0.00 T）。 被测模型 `BlockVariantPolicy` 仅 **24,915** 参数，块图按控制数缓存为**常量**，判别信号全部来自 34 维上下文（§8.1）。

## 1. 评测口径

| 项 | 说明 |
|---|---|
| 实例 | 混合控制数大电路：区块数 30–60，**每个区块的控制数独立取自 {2..8}** |
| 布局 | 所有区块共用一块数据寄存器（控制位 0..n_max−1、目标位 n_max），ancilla 池复用 |
| 安全性判据 | 相对相位替换后，数据寄存器 Z 基**测量分布**与全精确电路一致（TV ≤ 1e-9） |
| 验证器 | `mixed_stress.MixedVerifier`，工作在 `d = 2^(n_max+1)` 的归约空间，**无 2^k 枚举** |
| 策略 | ① 全精确（基线）② 全相对（合法上界，通常非法）③ **验证器贪心** ④ **一次性阈值** |

验证器正确性（与完整电路仿真逐 mask 比对）：**72/72（混合实例）+ 80/80（同构）+ 124/124（随机）掩码，0 处不符**。

## 2. 第一步：一次性掩码修复（repair）

### 2.1 问题

阈值决策只看每个区块的独立分数，忽略**累积**安全性。深电路里原始掩码会降级 4–13 个区块，只要其中一个破坏安全，旧实现就整条回退 → 收益归零。

### 2.2 方法

```
repair(mask): 按置信度从低到高逐个丢弃已接受的降级，直到判据通过
```

`mask = 0` 恒安全，因此必然终止，**返回值永远安全**。

### 2.3 实测（深电路，h_prob = 0.5，2 条 44/60 区块电路）

| 电路 | 原始阈值掩码 | 纯回退（旧） | **修复后（新）** | 验证器贪心 |
|---|---:|---:|---:|---:|
| #1（44 块） | 174 T（**非法**） | 0 T | **15 T** | — |
| #2（60 块） | 261 T（**非法**） | 0 T | **27 T** | — |
| **均值** | **217.5 T（非法）** | **0.0 T** | **21.0 T** | **55.5 T（100% 安全）** |

修复平均丢弃 9.5 个区块；100% 的电路都触发了修复。

**结论**：修复把"全灭"变成"永远有收益、永远安全"，成本为零（无重训），但它恢复的是贪心的一部分收益（21.0 / 55.5 ≈ 38%）。

## 3. 第二步：奖励尺度修正（legal-headroom normalization）

### 3.1 问题

原 reward：

```python
value = (t_all_exact - t_final) / t_all_exact
```

分母是**绝对 T 数**，于是"最好能省多少"被深度稀释：4 块电路最好能省 ~15%，40 块电路只有 ~0.3%。深电路在梯度里几乎无声，而 `risk_penalty = −0.5` 是固定值 → 策略唯一能学到的就是"**什么都别降**"。

### 3.2 方法

```python
self.headroom = t_all_exact - t_all_relative          # 合法余量（全相对能给的最大节省）
value = (t_all_exact - t_final) / max(self.headroom, 1)
```

深/浅实例的奖励量级因此可比（都落在 [0,1]），"深电路少降、浅电路多降"的**深度条件化**行为才第一次可学。

### 3.3 A/B 实测（同 seed / 15 epoch / 同 held-out 池；只改 `--deep-fraction`）

| 指标 | 修前·基线 0.0 | 修前·课程 0.6 | **修后·基线 0.0** | **修后·课程 0.6** |
|---|---:|---:|---:|---:|
| 深电路·原始阈值安全率 | 0% | **100%** | 0% | **100%** |
| 深电路·一次性+修复 省 T | 6.0 | **0.8** | 5.6 | **4.1** |
| 深电路·贪心 省 T | 6.0 | 6.0 | 6.0 | 6.0 |
| 浅电路·一次性 省 T | 63.0 | **13.5** | 63.0 | **39.25** |
| 浅电路·贪心 省 T | 66.25 | 66.25 | 66.25 | 66.25 |

（深电路 = 8 条 held-out，nc=2、30–50 块；浅电路 = 12 条 held-out，2–7 块。）

**修正带来的提升（课程档）**：深电路一次性 **0.8 → 4.1 T（5.1×）**；浅电路 **13.5 → 39.25 T（2.9×）**，同时保住"深电路原始掩码 100% 安全"这一课程目标（修复丢弃数 8.0 → 0.0）。

### 3.4 诚实的边界

- 课程仍**用浅电路收益换深电路原始安全性**（63 → 39 T，−38%）。这是"单一标量阈值"的固有取舍。
- 该收益属于**健壮性**（少做修复），**不是**更多 T 门节省——纯修复已拿到贪心的 93%（5.6 / 6.0 T）。
- 因净收益为健壮性而非节省，`--deep-fraction` **默认 0.0（opt-in）**。

## 4. 第三步：深度条件化阈值（**已实现并实测**）

### 4.1 方法

先验证了"提高阈值"这条路——**无效**：深电路即使把阈值推到 τ=0.99，模型仍保留 6.6 个区块，原始掩码安全率只有 12%（模型排序好但**标定差**，抬阈值几乎不减少数量）。所以必须按**数量**而非概率做深度条件化：

```
k_max(blocks) = clamp(round(4 / sqrt(blocks)), 1, blocks)      # 浅电路 2–3 个，深电路 1 个
mask = 按分数取 top-k_max  →  验证器确认 / 修复兜底
```

实现：`mixed_stress.depth_budget()` + `top_mask()`，并在战报里与"阈值+修复"并列输出（`--num-tests` 任意）。

### 4.2 消融（held-out：16 条浅 + 12 条深，同一策略权重、同一判据）

| 指标 | 浅电路（n=16） | 深电路（n=12） |
|---|---:|---:|
| 原始阈值掩码 安全率 | 100% | **0%** |
| 深度上限掩码 安全率 | 100% | **100%** |
| 阈值 原始省 T | 43.3 | 24.8（**非法**） |
| 阈值 + 修复 省 T | 43.3 | **4.8** |
| **深度上限 + 修复 省 T** | **45.8** | 3.0 |
| 验证器贪心 省 T | **51.4** | **8.2** |

### 4.3 结论：**"既要又要"没有达成**

| 判据 | 目标 | 结果 | 达成 |
|---|---|---|---|
| 深电路原始阈值安全率 | ≥ 90% | **100%** | ✅ |
| 深电路一次性+修复 省 T | ≥ 5.0 | **3.0** | ❌ |
| 浅电路一次性 省 T | 相对优于基线 | 43.3 → **45.8（+5.8%）** | ✅ |
| 贪心省 T | 不变 | 8.2 / 51.4（与基线一致） | ✅ |

- **收获**：深度上限换来**原始掩码安全**（深 0% → 100%，零修复）与浅电路小幅增益（+5.8%）。
- **代价**：深电路省 T 比"阈值+修复"低 **37%**（3.0 vs 4.8），且两者都远低于贪心（8.2）。
- **原因**：固定上限无法复刻贪心"按置信度顺序逐个加、安全才留"的**序贯**逻辑；且当分数大量并列时 top-m 的选取不稳定——实测 **top-2 经修复后常退化为 0**（并列时"丢弃最不自信"丢掉的是另一个 bit，剩余集合 ≠ top-1）。

**部署建议**：默认继续用 **`阈值 + 修复`**（深电路更省）；只有当你需要"**零验证器调用的安全掩码**"时才用深度上限。贪心仍是收益最优。

### 5.2 贪心最优性（500 条随机电路的大样本实测）

**早期小样本（3 条手工可枚举实例）**：

| 电路 | oracle 节省 | 贪心节省 | 捕获率 |
|---|---:|---:|---:|
| 6 块 [8,6,6,8,6,7] | 72 T | 72 T | 100% |
| 8 块 [3,2,4,3,8,8,2,5] | 33 T | 33 T | 100% |
| 10 块 [2,7,2,5,7,4,4,3,7,3] | 12 T | 12 T | 100% |

据此写下的"贪心达到 oracle 的 100%"是**小样本**结论；下面的大样本把它修正掉。

**大样本（`oracle_vs_greedy.py`，500 条随机混合电路，5–12 块，控制数 ∈ {2..6}，h_prob = 0.7，逐条 2^k 全枚举求 oracle，seed 20261014）**：

| 指标 | 数值 |
|---|---:|
| 完全最优（y = x）实例 | **482 / 500 = 96.4%** |
| **聚合捕获率（Σ贪心 / Σoracle）** | **98.37%** |
| 单实例捕获率（均值 / 中位） | 98.7% / 100% |
| 平均缺口 | 0.558 T（中位 0，最差 60 T） |
| 回归 y = a·x + b（R² / 对 y=x 线 R²） | a = 0.930，b = 1.836（0.932 / 0.925） |

产物：散点图 `reports/figures/fig4_oracle_vs_greedy.{png,pdf}`、捕获率分布直方图 `reports/figures/fig4b_capture_histogram.{png,pdf}`、逐电路数据 `reports/figure_data/oracle_vs_greedy.json`。

图 `fig4b` 展示**逐电路捕获率**的分布形状：482/500 条死死钉在 **100 %**，其余 18 条散落在 37.5 %–90.9 % 的长尾上（平均 99.0 %，中位 100 %）——即"绝大多数完美、极少数塌陷"，这正是聚合 98.4 % 与逐点 96.4 % 两个数字同时成立的原因。

**结论修正**：贪心**不是**逐点最优，而是**聚合意义上 98.4%、逐点 96.4% 地逼近上限**。约 4% 的实例会少降级，最差一条只拿到 oracle 的 37.5%（60 T）。

**根因（`deviation_table` 与逐 mask 直接 `deviation()` 双重验证，逐位一致）**：安全约束**非单调**。
以 7 块、控制数 [5,3,3,6,5,5,4] 为例：mask {0,1,6} 的偏差 = 0.500（**不安全**），{0,1,2,6} 偏差 = 1.4e-14（**安全**），{0,1,2,4,6} 又回到 0.500。即"再多加一个区块反而重新变安全"。
因此任何**被拒就永不回看**的贪心都到不了那些**必须经过不安全中间态**才能抵达的最优点。已实测：多轮 multipass、1-swap 局部搜索、以及**只走安全中间态**的 beam(64/256/1024) 均**未**把 96.4% 抬高（beam 逐点还常更差，因为按 t_count 剪枝会丢掉最优组合）。

**实践含义**：k ≤ ~20 时（2^k 可枚举）直接跑穷举 oracle 即得 100%；在 k = 30–60 的大电路上，贪心以 ~98% 的聚合捕获率、O(k) 次验证器调用在线运行——这正是它被部署的原因。

### 5.3 物理天花板：H 门密度决定一切

h_prob 扫描（10 条混合电路/档，seed 20261012，同一批电路形状）：

| h_prob | All-Exact T | 贪心省 T | 贪心捕获率 | 全相对安全率 | 一次性省 T（旧·纯回退） |
|---:|---:|---:|---:|---:|---:|
| 0.00 | 2221.8 | **952.2** | **100.0%** | 100% | 325.2 |
| 0.10 | 2221.8 | 59.1 | 6.2% | 0% | 0.0 |
| 0.30 | 2221.8 | 54.9 | 5.8% | 0% | 0.0 |
| 0.50 | 2221.8 | 47.4 | 5.0% | 0% | 0.0 |
| 0.80 | 2221.8 | 50.4 | 5.3% | 0% | 0.0 |

**只要下游存在 Hadamard，修正就不再保持对角 → 合法余量从 100% 塌到 ~5%。** 这是电路结构问题，不是验证器或策略问题。

### 5.4 为什么"保守判据"（Pauli/支撑集追踪）不划算

同一批深电路上，把**精确判据**换成**保守判据（Ω 必须严格对角）**：

| 电路 | 精确贪心 | 保守贪心 | 损失 |
|---|---:|---:|---:|
| 36 块 | 30 T | 15 T | **50%** |
| 39 块 | 66 T | 27 T | **59%** |
| 38 块 | 36 T | 21 T | **42%** |
| h_prob=0 时 | 588/978/714 T | 同左 | 0% |

归约验证器对**深度**是多项式、对**宽度**才是指数；当前数据宽度只有 9 个数据比特，所以换保守验证器**既不会更快、还会损失约一半余量**。

**支撑集/对角性追踪器（`support_tracker.py`）的直接实测**（O(gates) 时间、O(qubits) 空间）：

| 池 | 精确贪心 | 追踪器贪心 | 损失 | 不安全性 |
|---|---:|---:|---:|---:|
| 浅电路 n=16 | 51.4 T | 22.9 T | **55.5%** | 0 |
| 深电路 n=12 | 8.2 T | 3.0 T | **63.6%** | 0 |

- **可靠性**：对 152 个 mask 逐一与精确验证器比对，**0 次把不安全掩码判为安全**（这正是它存在的理由）。
- **保守性**：它在 mask 级别只接受 **8%** 的掩码；在可部署的贪心里损失 **55.5%（浅）/ 63.6%（深）**——比 §5.4 上半部分用矩阵判据估的 42–59% **更差**（追踪器比矩阵"Ω 对角"更保守）。
- **可扩展性**：单次判定 0.04–0.08 ms，50 区块的完整贪心 2.6–5.0 ms，与宽度无关、只随门数线性增长。

### 5.5 tracker 双向核验（precision + recall，分 H 密度）

**动机**：此前"`support_tracker` sound"只是**单向证据**（接受 ⟹ 精确也接受），
从未测过**保守度**（精确接受而 tracker 拒绝）。而 H 窗口实验要用 tracker 数"合法比例"，
若 tracker 保守，测到的就是**判定器的保守度**，不是真实适用率。

脚本 `tracker_verification.py`：在**精确验证器可用**的规模上（`blocks=6`、`controls∈{2,3,4,5}`、
每档 3 个种子、**全枚举 2^6 = 64 个掩码** ⇒ 每档 768 个掩码，共 **3840 个**）。

| h_prob | 掩码数 | 精确判合法 | tracker 接受 | **UNSOUND** | **recall（全掩码）** | 单点合法 | **单点 recall** |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.0 | 768 | 768 | 768 | **0** | **1.000** | 72 | **1.000** |
| 0.1 | 768 | 504 | 50 | **0** | **0.099** | 57 | **0.351** |
| 0.3 | 768 | 152 | 28 | **0** | **0.184** | 34 | **0.412** |
| 0.7 | 768 | 48 | 24 | **0** | **0.500** | 24 | **0.500** |
| 1.0 | 768 | 88 | 24 | **0** | **0.273** | 30 | **0.400** |

**结论：**

1. **precision 完美**：3840 个掩码、60 个实例上 `UNSOUND = 0`。tracker 的"接受 ⟹ 安全"在实测上无可挑剔
   （且"对角 ⟹ 测量统计不变"本身是一行定理，经验核验的是门规则的共轭记账）。
2. **recall 很低，而且不是单调的**：全掩码 recall 在 `0.099 – 0.500` 之间，
   **单点（单个块降级）recall 在 `0.351 – 0.500`**。
3. **⚠️ 我上一轮的预测被推翻**：我猜"保守度集中在 H 密集区、H-free 时接近全接受"。
   实测是 **h=0.0 时 recall=1.000（对），但 h=0.1 时全掩码 recall 只有 0.099，是全部档位里最差的**——
   低但不为零的 H 密度恰恰是 tracker 最保守的地方，而**那里正是余量存在的地方**。
4. **对下一步的直接影响（承重）**：**H 窗口实验不能用 tracker 当合法性 oracle。**
   用 tracker 数合法比例会**低估真实合法率约 2–3 倍**（单点 recall 0.35–0.50）。
   合法率必须在**精确验证器可用的规模**上直接测，再把 tracker 的数字作为**带实测 recall 界**的下界外推。

（限制：仅 `blocks=6`、4 种控制数、3 个种子；精确验证器为归约版（`d = 2^(n_max+1)`）；
"单点 recall" 只统计 1-bit 掩码。）

①"该**族**上**可达节省的绝对值**随 H 密度下降约 4.5×"；
②"**逐块**合法率缓降至约 **20%** 的地板"；
③删除"捕获率 5%"（非法分母）。

### 5.7 tracker 过保守的根因定位（第一条放宽规则）

**假设**：tracker 把**第一次** H 命中支撑集当成**永久 broken**，但 `H X H = Z` ——
经过**偶数个** H 的修正会重新变成 Z 型（对角），本该被接受。

**诊断**（`tracker_relaxation_diag.py`）：对每个"精确判合法但 tracker 拒绝"的掩码，
重放 tracker，找第一次被 H 命中的量子位，数它**其后**还有几个 H；偶数则记为"可恢复"。

| h | 精确合法 | tracker 接受 | **拒绝但合法** | **可恢复（偶数 H）** | 占比 |
|---:|---:|---:|---:|---:|---:|
| 0.1 | 656 | 132 | 524 | **406** | **0.77** |
| 0.3 | 244 | 24 | 220 | **138** | **0.63** |
| 0.7 | 88 | 24 | 64 | **36** | **0.56** |

**结论：56–77% 的召回损失由单一机制解释**——"H 命中即永久 broken"是**过强的规则**。

**第一条放宽规则（待实现 + 回归）**：把 `broken` 这个布尔量换成**每个量子位的 X/Z 类型标记**：

- 注入修正 → 相关量子位标记为 **Z 型**；
- H 作用在已标记的量子位 → **翻转**该位的类型（Z↔X）；
- CNOT / 块 的支撑传播沿用（并携带类型）；
- **末端"无 X 型分量残留"才算安全**。

这与旧规则的区别：旧规则在第一次 H 就永久拒绝；新规则允许 `Z → X → Z` 的恢复。
按本表占比估计，单块 recall 有望从 **0.35–0.50 提到约 0.70–0.85**。

**硬性要求**：实现后必须跑同一套 **3840 掩码全枚举回归 + 对抗采样**，
**UNSOUND 必须仍为 0**。放宽规则的正确性**只能由回归保证，不能由推断保证**——
这是一条 sound 性主张，错一次整个认证器就作废。

### 5.9 两层级认证器的收益：支撑宽度分布（预注册判定 → **分叉**）

方案：第一层 v1（快、sound、保守）；第二层对 v1 拒绝的掩码，取其**可靠支撑上界**（v1 传播的支撑集），
若宽度 `W ≤ 10` 则在窗口上**精确判定**（`2^W`）。预注册规则：若 `W≤10` 覆盖率 > 30% 就做。

**PART A（≤11q，有真值）：召回损失的支撑宽度**

| h | 召回损失数 | 中位 W | 最大 W | ≤6 | ≤8 | **≤10** | ≤12 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.1 | 524 | 7 | 9 | 40.1% | 74.0% | **100.0%** | 100.0% |
| 0.3 | 220 | 5 | 9 | 69.1% | 79.1% | **100.0%** | 100.0% |
| 0.7 | 64 | 3 | 9 | 81.2% | 90.6% | **100.0%** | 100.0% |

**pooled 808 条损失，`W≤10` 覆盖率 = 100% → 按预注册规则：BUILD。**

**PART B（24/50/100q，无真值）：v1 拒绝的掩码支撑宽度**

| 宽度 | 块数 | 中位 W | 最大 W | ≤6 | ≤8 | ≤10 | ≤12 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 24 | 40 | 30 | 30 | 5.0% | 5.0% | 10.0% | **10.0%** |
| 50 | 40 | 54 | 56 | 0.0% | 0.0% | 5.0% | **10.0%** |
| 100 | 40 | 95 | 106 | 0.0% | 0.0% | 5.0% | **5.0%** |

**四条结论：**

1. **机制成立**：在小电路上，**100% 的召回损失其支撑宽度 ≤ 10** → 一个 `W≤10` 的两层认证器能把它们**全部救回**，
   而且是**按构造 sound**（第二层是精确计算）。这比 v2 强得多。
2. **但在最需要它的地方失效**：`>20q` 时支撑宽度**随电路宽度增长**（100q 中位 95），窗口覆盖率只剩 **5–10%**。
3. **关键变量是"电路连通性"，不是宽度本身**：Part B 用的是**最坏情形**——层作用在**全部**数据比特上，
   CNOT 把支撑摊满整个寄存器。真实电路（加法器、QROM、比较器）是**局部连通**的，支撑很可能保持在界内。
   ⇒ **必须在真实电路族上重测**（与 H 窗口实验用同一批电路）。
4. **一个有讽刺意味的闭合**：`≤11q` 上两层认证器能救回**一切**，但那里**不需要它**（精确验证器本来就便宜）；
   `>20q` 上需要它，但窗口**饱和**。所以它的价值恰好落在**交叉点**——"精确验证器太慢、但支撑仍有界"的那一段。
   **这段是否存在，取决于真实电路的连通性，是目前唯一还开放的改进空间。**

### 5.10 **撤回 §5.9 的 BUILD 判定**：那是天花板效应，不是局部性

**实测寄存器规模：**

| 族 | 配置 | N_total |
|---|---|---|
| Part A（同构，controls 2/3/4/5） | 3 / 5 / 7 / **9** | **max N = 9** |
| Part B（WideInstance，ancilla pool = 6） | width+6 | **30 / 56 / 106** |

**两条修正：**

1. **Part A 的"W≤10 覆盖 100%"是恒真的**：N ≤ 9，所以 W 根本不可能超过 9
   （观测到的 max W 恰好是 9，三个 h 都一样——那是**贴着 N 的天花板**，不是局部性分布）。
   它度量的是"**电路太小**"，不是"窗口是局部的"。⇒ **按预注册规则得出的 BUILD 判定撤回。**
2. **Part B 的"W > 宽度"不是 bug**：W ≤ N_total = width+6，而观测到的 W **恰好等于** 30/56/106。
   上一轮表里的"宽度"一列只数了**数据比特**，是我标注不清。**真实情况是 W = N_total，即完全饱和（W/N = 1.0）。**

**修正后的统一结论**：**Part A 与 Part B 说的其实是同一件事——残差支撑会把整个寄存器摊满。**
于是"在 W 个量子位上做 `2^W` 精确计算"就等于做**全量精确计算**，**两层认证器没有节省空间 → 默认关闭。**

**并且我上一轮那句"真实电路是局部连通的，支撑很可能保持在界内"推理有一步不成立**：
**连通性只限制扩散的速率，不限制最终的支撑大小**。残差是从块出发一直摊到**电路末端**的，
支配量是**尾部长度**（该块到末端经过的门数/层数），不是"每次 CNOT 只碰两个比特"。
只有当尾部被**短的 H 窗口**截断时，支撑才会小。

⇒ **真实电路测量必须新增一个变量**：每块残差的**尾部长度**，并报 `W` 与尾部长度的关系。
**现在唯一还开放的问题是**：真实电路上是否存在"尾部被短 H 窗口截断"的块，使 `W ≤ N/3`。
若不存在（先验：宽电路上不存在）→ **两层认证器永久关闭**，按 v1 定稿。

**同时**：预注册规则必须改成**尺度不变**的形式，例如
"某族上 `W ≤ N/3` 的损失掩码占比 ≥ 30% **且** 该族 `N ≥ 40` 时才做第二层"——
绝对阈值 `W ≤ 10` 在 11 比特和 100 比特上是两件完全不同的事。

### 5.19 `relative_phase_metrics` 语义钉死：**它只检查"右乘序"**

**源码**（`Linux-MCX:251-291`）：

```python
keep = [x for x in range(2**total) if all(not (x >> a) & 1 for a in ancillas)]  # clean-ancilla 子空间
correction = U_ideal.conj().T @ U_candidate          # <<< 注意顺序
offdiag = max|correction - diag(correction)|
unit    = max||diag(correction)| - 1|
接受 ⟺ offdiag < 1e-8 且 unit < 1e-8
```

⇒ 它检测的是 **`U_cand = U_ideal · D`（右乘对角修正）**。

**而项目自己的构造是左乘**：`block_diagonal` 的文档写明 `B_relative = D · B_exact`。

**决定性微观检验**（2 量子位，`D` 为对角酉）：

| 候选 | `\|U_cand\| = \|U\|`（测量安全） | `relative_phase_metrics` |
|---|:--|---|
| `U_cand = D·U`（**左乘**，= 我们的构造） | **True** | **(0.7071, 0.2929) → 拒绝** |
| `U_cand = U·D`（右乘） | True | (0.0, 0.0) → 接受 |

**两种顺序都测量安全**（`|D U| = |U| = |U D|`），但这个函数**只接受右乘序** ⇒ **它对我们的构造误拒**。

**四条后果：**

1. **正确判据是逐元素幅度相等 `|U_cand| = |U_ideal|`**（等价于"**任一顺序**的对角修正"），而不是只查一个顺序。
2. **§5.15 / §5.16 的"真值"列确认作废**（它们用的就是这个函数）。
3. **§6 的"相对相位合法 ✅"列必须用新判据重审**：若整条电路的**合成**修正恰好落在右乘序，结论不变；
   否则 §6 的合法列**低估**了合法性（方向对我们有利，但判据必须写准）。
4. **tracker 未被证伪**，而且在争议位点上**逐元素判据与它一致**（§5.18 的直接计算：C 对角 ≈ 1e-16）。

重跑 §5.15 / §5.16 / §6 的合法列。**在此之前，合法性与紧致度相关的一切数字不得进论文。**

（`unary(4)`：`ccx = 2` **且** `t = 4, tdg = 4`），所以 `7m` 根本不是真实 naive，`FR > 7m` 是我的模型错，不是数据错。

| 类 | n | m | k | k/m | naive | ours | FR | **GAIN = FR − ours** |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| one-hot QROM | 4 | 10 | 10 | **1.00** | 132 | 102 | 108 | **6** |
| **unary iteration** | 3–6 | 1–4 | = m | **1.00** | 7–76 | 4–64 | 7–72 | **3 / 6 / 7 / 8** |
| 比较器网络 | 2–4 | 3–9 | 0–1 | 0–0.33 | 21–63 | 12–36 | 15–31 | 3 / 0 / 0 |
| modexp（链式加法器） | 2–4 | 12–24 | **0** | 0.00 | 84–168 | 48–96 | 28–40 | **0** |
| Grover oracle | 3 | 2 | 0 | 0.00 | 14 | 8 | 14 | 6（改写**不合法**，不计） |

**两条结论：**

1. **`k/m = 1` 并没有转化为可观的 GAIN**：unary 的增益只有 **3 → 6 → 7 → 8**（次线性），
   one-hot QROM（`k/m = 1`）只有 **6**。原因：**强基线也在优化 `ccx` 之外的自由 T 门**，
   而我们的 pass **只动 `ccx`** —— 两边各赢一半，净差被稀释。
2. ⇒ **按预注册规则：D 缺乏已证实的靶子。**
   §5.34 里那个**线性 `3m`** 只出现在**手工构造的纯 `ccx` 电路**（AND 树、compute-only 前缀）；
   一旦换成**真实综合产物**（Qiskit 的 mcx 会留下自由 T），优势就降到 **O(1)–O(10)**。

**诚实的边界（必须写）**：本表的"真实类"是**结构类比**（QASMBench/RevLib 离线不可得），
且比较里混合了**综合风格**的差异（Qiskit 的 gray-code MCX vs 纯 Toffoli 构造）。
⇒ 只能写成"**在这些类比类上，松弛增益为 0–8 T**"，**不能**推广为"所有真实电路"。

**判定**：**D 关闭（缺乏已证实的靶子）**；T 门减少的方向转 **C（测量式 AND）**；
认证器按**工具论文**收尾（相对真实 Qiskit L3 −33…−37%、`O(门数)`、任意宽度、附证书）。

### 5.37 3 天探针（第 1+2 天）：测量式反计算 → **57% 节省、精确、且让判据问题消失**

对象：CDKM 加法器，把**每个 Toffoli** 换成测量式的 temporary-logical-AND
（`H;T;CX;Tdg;CX;T;H` = 4 T 且**确定性** AND → `measure` → `if m: X(target)`）。

| 对象 | Toffoli | naive | RCCX（至多差对角） | **测量式（精确）** |
|---|---:|---:|---:|---:|
| CDKM adder(3) | 6 | 42 T | 24 T | **18 T** |
| CDKM adder(4) | 8 | 56 T | 32 T | **24 T** |

动态资源：6–8 次 `measure`、6–8 次 `if_else`、6–8 个 ancilla。**节省 vs naive = 57%**（GO 门槛 15%）。

**(a) T-count → GO。** 而且测量式**同时优于**我们的 RCCX 路线（`18 < 24`、`24 < 32`），**并且是精确的**。

**(b) ⚠️ 现有 tracker 不适用，而且是"静默失效"——本轮最重要的一条。**
`RB._tracker_schedule` 对含 `measure` / `if_else` 的电路**不报错**：它把这些未知门直接塞进 layer，
而 `ST.track_safe` 的 `apply_layer` 对**未知门名不做任何处理** → **完全忽略测量与经典前馈**，
于是会给出**建立在错误模型上的"安全"判定**。
⇒ **必须立刻修（与选不选这条路线无关，这是安全缺陷）**：
`_tracker_schedule` / `track_safe` 遇到**未建模的门型**（`measure` / `if_else` / `reset`）应当**显式拒绝**。

**(c) 最小判据问题"消失"了。** 测量式 AND 是**精确**的电路恒等式（逐构造验证），
**不需要任何逐实例合法性判据** → **动态场景下"合法性认证"问题不复存在**（与预判一致）。

**GO / KILL 判定**：
- **GO（自动化 + T-count）**：57% 节省、优于 RCCX、且精确；
- **KILL（以"认证"为核心）**：动态路线**不需要证书**。

**战略后果（改变定位的一句）**：测量式路线在 **T-count 与精确性上都优于**我们的相对相位路线。
⇒ 认证器的生态位被**进一步压窄**，但也**第一次能被一句话说清**：

> **我们的路线是"无 ancilla、无测量、无经典控制"的那一条**——它用**一个可证明的合法性证书**
> 去换掉"ancilla + 动态控制"这三样资源。

这反而可能是**工具论文最强的定位句**：
在**不引入 ancilla、也不要求硬件支持中途测量/前馈**的约束下，我们给出
**相对默认链 −33…−37% 的 T-count 下降 + 任意宽度的合法性证书 + 实测紧致度**。

### 5.38 **撤回 §5.37 的探针结论**：gadget 根本不成立

**机械核验（审阅指出）**：gadget 串 `H;T;CX;Tdg;CX;T;H` 里 **T 门数 = 3，不是 4**（我 docstring 写错）；
因此 `18 T = 3×6` 与"每门 4 T"**自相矛盾**。

**逐门验证（决定性的那一测）**：对 4 种控制组合（ancilla 初态 `|0⟩`）算 `P(a=1)`：

| c0 | c1 | **P(a=1)** | 应为 AND |
|---:|---:|---:|---:|
| 0 | 0 | **0.1464** | 0 |
| 0 | 1 | **0.1464** | 0 |
| 1 | 0 | **0.1464** | 0 |
| 1 | 1 | **0.8536** | 1 |

⇒ **ancilla 的测量不是确定的** → 这个 gadget **不是 AND**，`if a: X(t)` 只在 ~85% 的情形下正确
⇒ **改写后的电路不是精确等价的** ⇒ **§5.37 的"精确"、"18 T"、"57%" 三样全部作废，GO 撤回。**

**根因**：Gidney 的 temporary logical AND 需要 **catalysed ancilla**（初态不是 `|0⟩`，而是 `T|+⟩` 一类的态）。
我按"从 `|0⟩` 开始"写了一个**看起来像、但其实不成立**的 gadget——**这是"测试写错会掩盖 bug"的又一个实例**。

**而且分母也是软的**：`57%` 是相对"每门 7 T 的朴素"，而 Gidney 的加法器是 **`4n−4`**
（n=3 → **8 T**），我的 18 T 是它的 **2.25 倍**。
⇒ **探针没有证明任何"更省"，只证明了我实现了一个错的构造。**

**只有两条能保留（它们不依赖 gadget 是否正确）**：

1. **动态路线的"认证"轴确实死了**：测量式 AND 是**精确恒等式**（带经典修正），
   不需要"至多差一个对角"的判据 ⇒ **"认证"不能作为 B 的贡献**；
2. **`tracker` 对 `measure` / `if_else` 静默失效**（见 §5.37(b)）——**安全缺陷，必须显式拒绝**。

**方法学（第 6 次同类问题，且这次由审阅在第 3 天抓到）**：
> **任何"我们更省了"的主张，分子分母都必须机械导出；分母必须是最强基线，不能是朴素基线；**
> **任何 gadget 主张都必须有一条"它真的实现了目标函数"的数值断言**（本例：`P(a=1)` 必须等于 AND）。

## 6. 真实电路 SOTA 对比

> 数据源：`reports/figure_data/realworld_sota.json`（由 `realworld_benchmark.py --json` 直接生成，非手抄）。
> 复现：`.venv/bin/python realworld_benchmark.py --size-map "mcx:3,4,5;adder:3,4,8,16,32;grover:3" --todd-timeout 60 --json reports/figure_data/realworld_sota.json`

这一节把编译器放进**外部基线**里：Grover、CDKM 加法器（3 → 32 bit，跨越 20 比特内存墙）、
以及本项目自己的 C^nX 阶梯，与 **Qiskit 默认优化器**和 **TODD（Heyfron & Campbell 2019）**正面对比。

### 6.1 对照设置

| 列 | 含义 |
|---|---|
| `L0` / `L3` | Qiskit 转译到 Clifford+T，`optimization_level` = 0 / 3（"默认优化器"基线） |
| `TODD` | **PyZX `phase_block_optimize`** —— Heyfron–Campbell TODD 的实现，按 Hadamard 分块施加；`--todd-timeout` 默认 60 s，超时记 `timeout` |
| `ours` | 本项目的相对相位改写：Toffoli → 4-T RCCX，纯 C^nX → 整块 RCCX 阶梯，**仅在注入的对角修正被认证存活时采用** |
| `FR` | **pyZX `full_reduce` + `extract_circuit`** —— ZX 图完整化简后提取电路，实测与原电路**精确等价**（err ≈ 5e-15）；本表的**最强基线** |
| `TODD(ours)` | 在**我们的电路之上**再跑一遍 TODD —— 检验是否还有被我们漏掉的优化 |
| `best` | TODD / **FR** / ours / TODD(ours) 中的最优值；**非法的相对相位改写不计入** |
| 认证方式 | `Exact Verifier`（≤ 11 qubits，构造 `2^N` 算符）或 `Support Tracker (OOM-free)`（> 11 qubits，`O(gates)` 对角性追踪） |

所有电路都要求可表示为 **Toffoli + Clifford**（否则 T-count 没有定义）。Qiskit 的
`MCXGate(n>=3)` ancilla-free 综合使用 π/8 旋转，**不属于 Clifford+T**，因此不进入本表
（Grover(n>=4) 因此被自动跳过）。

| CDKM 4-bit | 10 | 10/10/10 | 85/**57**/165 | 32/32/**10** | 98/**86**/103 | 0.17 s |
| CDKM 8-bit | 18 | 18/18/18 | 169/**113**/322 | 64/64/**24** | 194/**170**/228 | 0.47 s |

**三条读法**（每一条都是实测，不是外推）：
1. **辅助位无差异**：三条路径的量子位数完全相同（`L0 = ours = FR`），所以深度差**不是**辅助位造成的。
2. **ours 省的是 Clifford 门与总深度**：加法器上 `43 vs 132` 门（−67%）、总深度 `65 vs 98`（−34%）；32-bit 上是 `449 vs 1365`、`674 vs 868`。
3. **FR 省的是 T-depth**：加法器上 `9/10/24/41/58` vs 我们 `24/32/64/128/256`（好 2.7–4.4×）。**这是一次明确的 Pareto 权衡。**

### 6.5 结论（换掉弱基线之后的真实版）

1. **加法器上我们对最强基线 `FR` 的 T-count 优势 = 0**：`24/32/64/128/256` 逐位相同，8q 到 66q 都成立。
   我们原有的"比 TODD 少 33%"**只是相对弱例程**（`phase_block_optimize`）成立，**不能**写成对 SOTA 的优势。
2. **阶梯上的 T-count 优势不随规模增长（§6.10）**：3–40 控制位实测 `FR − ours` **恒为 +3 T**，相对优势从 25%（n=3）单调衰减到 **1.0%（n=40）**。因此"10–20%"只是小 n 效应，**不能**当 scaling claim；只能写"恒定省 3 T"。
3. **与 `FR` 是 Pareto、不是全面胜负**：我们赢 **Clifford 门数（−67%）与总电路深度（−34%）**，`FR` 赢 **T-depth（2.7–4.4×）**；
   T-count 在加法器上打平、在阶梯上我们赢。
4. **`TODD(ours) = ours` 依然成立**（8 条合法电路全部），即没有"被我们漏掉的优化"。
5. **可扩展性仍是我们的**：`FR` 在 66q 要 **57 s**，TODD 在 34q 就 60 s 超时，而我们**认证**只要 **0.3–2.4 ms**；
   不过要诚实写清楚：**`FR` 能做优化、我们做的是结构改写 + 多项式认证**，两者的可扩展性不是同一件事。

### 6.6 跨越 20 比特内存墙：优化器会超时，我们的认证不会

- **认证方式自动切换**：`≤ 11` qubits 用精确验证器（构造 `2^N` 算符，34q 就要 `2^34`，不可行）；
  超过即切换到 `support_tracker.py` 的**对角性追踪**（`O(gates)` 时间、`O(qubits)` 空间）。
  **交叉校验**：把同两个小加法器强制走 Tracker（`--exact-limit 0`），结论与精确验证器**完全一致**，
  耗时 `0.1 ms` vs `96 ms / 2363 ms`（约 1e3–2e4×）。运行：
  `.venv/bin/python realworld_benchmark.py --circuits adder --qubits 3,4 --exact-limit 0`
- **T-count 线性外推**：CDKM n-bit 加法器有 `2n` 个 Toffoli，`ours = 4·(2n) = 8n`，
  Qiskit L3 `= 6·(2n) = 12n` → 恒定 **−33%**；32-bit 实测 `384 → 256`，与公式一致。
- **优化器的可扩展性**：`phase_block_optimize`（TODD）在 34q / 66q 上 60 s 未收敛；`full_reduce`（FR）**没超时**但需要 **5.86 s / 57.01 s**。
  而在**我们已降级的电路上**再跑 TODD 只要 6.1 s / 45.9 s，且结果**等于 ours**（无额外收益）。
- **必须区分的两件事**：上一条讲的是**优化**的可扩展性；我们的 **0.3 / 2.4 ms** 是**认证**（判合法性）的耗时。
  论文里只能写"我们的**认证**在 34–100q 上是 ms 级"，**不能**写成"我们的优化比 pyZX 快"。

### 6.7 三条限制

1. **t-par 不是 T-count 基线，而且当前环境没有它的实现。**
   Amy–Maslov–Mosca 2014 的 t-par 优化的是 **T-depth**（用额外辅助比特换深度），
   **T-count 通常会变高**。所以本节的 T-count 对照用 TODD 是正确的；若要给出 T-depth 结论，
   需要一个 t-par 实现（`pytket` / `tweedledum` 均未安装，PyZX 也没有）。
   这是本报告**尚未覆盖**的一块，不应含糊带过。
2. **34q/66q 的 "timeout" 是 PyZX 实现的墙钟现象，不是"TODD 做不到"的定论。**
   换更快的实现 / 更长的预算可能压出更低的 T-count；论文里应写"60 s 预算内未返回"，
   不能写成"TODD 无法处理"。同时 `ours` 在 34q/66q 上仍只是**下界**（Tracker 是充分判据）。
3. **结果仍是"子电路级"的。** 认证的是"该电路以 Z 基测量收尾"时对角修正无害；
   加法器与 MCX 阶梯都是**子程序**，嵌进下游还有 Hadamard 的更大算法时必须对**整条电路**重判 ——
   按 §5.3 的 H 断崖多半会失效，Grover 就是现成反例。TODD 版本为 PyZX 0.10.6。

### 6.9 FR 公平性核验：给 FR 加 Clifford/深度后处理（已做）

质疑："FR 的 Clifford 数比 Qiskit L3 还高一倍，说明它没跑提取后的 Clifford 化简；我们的两条优势（Clifford −67%、总深度 −34%）可能是假象。"

实测（对 FR 输出加四种标准后处理，同一调度器测量）：

| 电路 | 变体 | T-count | **T-depth** | **Clifford** | **总深度** | 门数 |
|---|---|---:|---:|---:|---:|---:|
| CDKM 3-bit | **ours** | 24 | 24 | **43** | **65** | 67 |
| | FR（原始） | 24 | **9** | 132 | 98 | 156 |
| | FR + `full_optimize` | 24 | 19 | 120 | 92 | 144 |
| | FR + `clifford_simp` | 24 | 10 | 131 | 110 | 155 |
| | FR → Qiskit L3 | 24 | 19 | 242 | 149 | 266 |
| CDKM 8-bit | **ours** | 64 | 64 | **113** | **170** | 177 |
| | FR（原始） | 64 | **24** | 322 | 228 | 386 |
| | FR + `full_optimize` | 64 | 52 | 340 | 235 | 404 |
| | FR → Qiskit L3 | 64 | 53 | 575 | 335 | 639 |

**结论（与质疑方向相反）**：四种后处理都**没有**把 FR 的 Clifford 数与总深度拉向我们——
它们仍在 `120–575` / `92–335`，即我们的 `2.8–5×`；Qiskit L3 反而**更差**（重综合加门）。
同时 FR 的最佳 T-depth 来自**原始提取**（9/10/24），任何后处理都让它**变差**（19/23/52）。
所以 §6.3 的 Pareto 结论（我们赢 Clifford 与总深度、FR 赢 T-depth）**在加了后处理之后依然成立**。

**仍未排除的**：`zx.optimize.basic_optimization` 在提取出的 `SWAP` 门上直接崩溃
（`TypeError: Unknown gate SWAP`），pytket 未安装，因此"**任何**标准 Clifford 后处理都不能缩小该差距"
这句话**不能**说；只能说"我能跑到的四种都不能"。

### 6.10 阶梯 Scaling 实测（3–40 控制位）：优势**不随规模增长**

把 §6.2 的阶梯从 3 个点扩到 11 个点（C³X … C⁴⁰X），`ours` = 本项目的相对相位 AND 阶梯，

| 3 | 5 | 12 | 21 | 15 | **+3** | 25.0% | 8 | 8 | 15 | 55 | 0.0 s |

| 8 | 15 | 52 | 91 | 55 | **+3** | 5.8% | 28 | 30 | 65 | 230 | 0.3 s |
| 10 | 19 | 68 | 119 | 71 | **+3** | 4.4% | 36 | 16 | 85 | 282 | 0.4 s |
| 12 | 23 | 84 | 147 | 87 | **+3** | 3.6% | 44 | 32 | 105 | 371 | 0.8 s |

**结论（对上一轮的"10–20% 优势"是坏消息）：**

1. **`FR − ours` 恒为 +3 T**，与 n 无关：`ours = 8n − 12`、`FR = 8n − 9`。

2. **机制**：相对相位自由度在这个阶梯上只值**一个常数 3 T**（不是 3×Toffoli）——

3. **T-depth 也大多输给 FR**（n=40：`156 vs 102`；仅 n=3/4 打平、n=8 我们略好）。
4. **仍然成立的只有 Clifford 门数**：n=40 `385 vs 1416`（**3.7×**），全 n 一致。
5. `FR` 耗时随 n **超线性**增长（0.3 s → 2.2 s → 10.3 s → 84.0 s，n 翻倍约 10×），
   而我们的**认证**在 34–66q 是 0.3–2.4 ms——这条生态位论证仍然需要（§6.6/§7）。

### 6.11 定价律（同族受控实验）：相对相位松弛 = **3 T × 未配对 Toffoli 数**

上一轮的"阶梯 gap=3、加法器 gap=0"是**跨族拟合**，可能只是巧合。本轮做**同族受控实验**：
取 CDKM 加法器的 canonical 电路，在**不同位置截断**门序列，得到"未配对 Toffoli 数 k 可变"的一组变体，
逐个实测 `gap = FR_T − ours_T`。

**当时的判定谓词**（§6.12 已证明它**过强**）：把每个 Toffoli 记作**有序**三元组 `(c0, c1, target)`，
k = 出现奇数次的唯一有序三元组个数。**§6.12 的反例表明控制位顺序不影响该门，故必须换成代数定义。**

| n | 截断门数 | Toffoli 数 | **未配对 k** | ours T | FR T | **gap** | **预测 3k** | 定律成立 |
|---:|---:|---:|---:|---:|---:|---:|---:|:--:|
| 4 | 3 | 1 | 1 | 4 | 7 | **3** | 3 | ✅ |
| 4 | 7 | 2 | 2 | 8 | 14 | **6** | 6 | ✅ |
| 4 | 11 | 3 | 3 | 12 | 21 | **9** | 9 | ✅ |
| 4 | 15 | 5 | 3 | 20 | 29 | **9** | 9 | ✅ |
| 4 | 18 | 6 | 2 | 24 | 30 | **6** | 6 | ✅ |
| 4 | 22 | 7 | 1 | 28 | 31 | **3** | 3 | ✅ |
| 4 | 25 | 8 | 0 | 32 | 32 | **0** | 0 | ✅ |
| 6 | 5 | 1 | 1 | 4 | 7 | **3** | 3 | ✅ |
| 6 | 11 | 3 | 3 | 12 | 21 | **9** | 9 | ✅ |
| 6 | 16 | 5 | 5 | 20 | 35 | **15** | 15 | ✅ |
| 6 | 22 | 7 | 5 | 28 | 43 | **15** | 15 | ✅ |
| 6 | 27 | 9 | 3 | 36 | 45 | **9** | 9 | ✅ |
| 6 | 33 | 11 | 1 | 44 | 47 | **3** | 3 | ✅ |
| 6 | 37 | 12 | 0 | 48 | 48 | **0** | 0 | ✅ |

**结论：`gap = 3k` 在 14/14 个点上精确成立（k = 0,1,2,3,5）。**

- 两个家族都是这条定律的实例：**阶梯**有 1 个未配对的中心 Toffoli → gap 恒为 3（因此相对优势随 n 衰减）；
  **CDKM 加法器**的 MAJ/UMA 全部配对 → gap 恒为 0。
- **机制**：成对的 compute/uncompute 让 Toffoli 的 π/4 相位在**相位多项式**里相消，精确优化器（FR）也能降到 ≈4 T/门；
  只有**未配对**的那个必须付 7 T，正好比相对相位版多 **3**。
- **本轮尚未做的**：机制只在**计数谓词**层面被验证，还没有在相位多项式残差上**直接**确认相消。
  这是下一步（决定这条定律是"拟合"还是"机制"）。

**这条定律把上两轮的"失败"（阶梯不 scaling、加法器归零）变成了同一个定律的两个实例**，
并且给出了真正可主张的东西：**相对相位松弛的定价 = 3 T × 合法且未配对的 Toffoli 数。**

### 6.12 机制验证与 k 的代数化：语法谓词被反例推翻

**（1）算子残差 `R = RCCX · CCX†`（3 量子位，实测）**

| 量 | 值 |
|---|---|
| `max\|R − diag(R)\|` | **1.1e-16**（完全对角 → 相对相位修正确实是 Z 型） |
| 对角元取值 | **`{1, −1, i, −i}`** |
| `R² = I`？ | **否**（`max\|R² − I\| = 2.0`） |

⇒ 单门残差是**4 阶**对角算子（不是对合），所以"两个同门自动相消"**不能**由单门残差推出；
相消来自**整条电路**的相位记账。这直接把定律从"单门恒等式"降级为"聚合层面的观测 + 机制"。

**（2）k 的反例检验：语法谓词被推翻**

| 构造 | ccx 数 | 语法 k（有序三元组） | ours T | FR T | gap | 3k | 结论 |
|---|---:|---:|---:|---:|---:|---:|:--|
| 同一门 ×2（成对） | 2 | 0 | 8 | 0 | −8 | 0 | FR=0（电路=恒等） |
| **控制位交换** `(0,1,4)+(1,0,4)` | 2 | **2** | 8 | **0** | −8 | 6 | **语法谓词判错**：二者是同一个门，真值 k=0 |
| 同一门 ×3 | 3 | 1 | 12 | 7 | −5 | 3 | 门等价于 1 个 Toffoli |
| 两个不同（真未配对） | 2 | 2 | 8 | **14** | **6** | 6 | ✅ `gap = 3k` |
| 链式 MAJ/MAJ/UMA/UMA | 4 | 0 | 16 | 0 | −16 | 0 | 电路=恒等 |
| CNOT 遮蔽副本 | 2 | 0 | 8 | 0 | −8 | 0 | — |

**结论：**

1. **语法谓词（有序三元组奇偶）是错的**——"控制位交换"这条反例直接把它推翻（它预测 k=2，真值 k=0）。
   与预判一致：**k 必须代数化**（至少要把两个控制位当**无序对**，并按**奇偶**而非按次数计）。
2. **修正后的闭式只在"非冗余"结构上成立**：`FR_T = 4m + 3k` 在**截断 CDKM 序列**上 14/14 成立，
   但在**冗余/退化**构造上**失败**（§6.13 A 表）。适用域必须显式限定为"每个 Toffoli 都被实际使用"的结构——
   否则审查者一算就抓到（本报告上一版的"逐点核对通过"就是一处**事实性错误**，已改）。
3. **本条定律的定位必须降级**：它是**"相对 pyZX `full_reduce` 的实测闭式"**，
   **不是**"精确最优的定价定理"——因为右边由 FR 的输出定义（换一个精确优化流程可能不同）。
   只有在拿到文献、确认"4 T 是 up-to-phase 下界、7 T 是精确下界、差 3"之后，才能升级为推导。
4. **新颖性风险**：单门 `7 − 4 = 3` 的记账很可能在本领域**已知**（Gidney 的 AND/加法器工作）。
   本工作的贡献应写成 **"聚合闭式 + 受控验证 + 可计算谓词"**，而**不是**"发现 3"。

### 6.13 定价律的边界与**判死**（预注册阈值）

**（A）算术核对：`4m + 3k` 在冗余构造上失败**

| 构造 | m | k（无序对奇偶） | `4m+3k` | 实测 FR | 结论 |
|---|---:|---:|---:|---:|:--|
| 控制位交换 `(a,b)+(b,a)` | 2 | 0 | 8 | **0** | **FAIL** |
| 同一门 ×3 | 3 | 1 | 15 | **7** | **FAIL** |
| 两个不同门（真未配对） | 2 | 2 | 14 | 14 | OK |
| MAJ/MAJ/UMA/UMA | 4 | 0 | 16 | **0** | **FAIL** |

**原因不是"定律失败"，而是比较的左侧 `ours = 4m` 是朴素替换**：在冗余电路上它白留门
（×3 那一行 `ours = 12`，而松弛类内的最优只要 4 T）。所以 `gap = 3k` 测的是
**"pyZX 输出 − 朴素替换"**，**不是**"松弛的价格"。要谈"松弛的价格"，必须先**在松弛类内做优化**——
这正是 §8.6 要回答的事。**结论：§8.6 从并行项升级为定价主张的前置条件。**

**（B）实算电路的 k/m（k 用无序控制位对奇偶，是**上界**；合法性用 tracker 原位判定）**

| 电路 | 量子位 | m | k | k/m | 合法 m | k_eff | **k_eff/m** | 判定 |
|---|---:|---:|---:|---:|---:|---:|---:|:--|
| CDKM 加法器 3-bit | 8 | 6 | **0** | 0.00 | 6 | 0 | **0.00** | **KILL** |
| CDKM 加法器 4-bit | 10 | 8 | **0** | 0.00 | 8 | 0 | **0.00** | **KILL** |
| CDKM 加法器 8-bit | 18 | 16 | **0** | 0.00 | 16 | 0 | **0.00** | **KILL** |
| 比较器 3-bit | 6 | 3 | 1 | 0.33 | 3 | 1 | 0.33 | keep |
| 比较器 5-bit | 10 | 7 | 1 | 0.14 | 7 | 1 | 0.14 | keep |

**预注册判死阈值 k_eff/m < 0.10**（先写后跑）：**中位数 = 0.000 → 判死。**

**判死含义**：在旗舰实算电路（CDKM 加法器）上，**未配对 Toffoli 数 k = 0**，
因此相对 `FR` 的净增益 **恒为 0**；定价律**没有实践含量**。
→ **定价律降级为"实现层的收益预测器/注记"，不再作为论文的中心主张。**

（限制：k 是**上界**（无序对奇偶），精确 k 需相位多项式残差；合法性只测了"单点降级"掩码；
比较器是唯一正例；仅 5 个电路，不是全库扫描。）

## 7. 超越归约验证器规模：24–100 数据比特的实测

> 数据源 `reports/figure_data/wide_scale_stress.json`（`wide_scale_stress.py` 直接落盘，240 条电路）。
> 复现：`.venv/bin/python wide_scale_stress.py --widths 24,32,50,100 --h-probs 0.0,0.1,0.5 --circuits 20`

### 7.1 前提：这个尺度上不存在精确 oracle

归约验证器的判据是"Z 基测量分布一致"，需要 `2^N × 2^N` 稠密算符。实测所需内存：

| 宽度 N | 精确验证器所需算符内存 | 标注 |
|---:|---:|:--|
| 24 | 4.0 PB | **Verifier: OOM (2^N)** |
| 32 | 2.6e5 PB | **OOM (2^N)** |
| 50 | 1.8e16 PB | **OOM (2^N)** |
| 100 | 2.3e46 PB | **OOM (2^N)** |

唯一 sound 的可行判据是 `support_tracker.py` 的**对角性追踪**（`O(gates)` 时间、`O(qubits)` 空间）。它在两种布局上都逐掩码对 2^N 精确矩阵校验过：

- `support_tracker.py --self-test`（同构布局）：**152** 个掩码，tracker 接受但真实修正非对角 = **0**；
- `wide_scale_stress.py --self-test`（**wide 布局**，含 ancilla 路径与 h=0.1/0.3/0.7/1.0）：**144** 个掩码，unsound = **0**。

注意 tracker 是**充分**判据（接受 ⟹ 安全）；被拒的掩码未必真不安全，故下列节省都是**下界**。

### 7.2 设置

宽度 24/32/50/100 数据比特；每块保留原生控制数 C²X…C⁸X，随机落在宽寄存器窗口上；层间 Clifford 作用在**全部**数据比特。每 (宽度, h_prob) 20 条电路、块数 20–60，共 **240** 条；策略权重冻结（`variant_policy_rl_best.pt`）。

关于"把块的局部导线重映射到 `0..15`"：**不需要**。`_block_graph(n)` 是块的规范局部 ZX 图（索引局部于该块，0..n+1），`context_features` 不含全局宽度项，所以冻结模型对同一控制数的块，在任何宽度、任何位置给出**完全相同**的输入张量。

### 7.4 结论

1. **可行性（最硬的一条）**：在 **100 数据比特、~40 个区块**的电路上，"打分 → 追踪 → 修复"全程 **~40 ms** 跑完；同一电路上精确验证器需要 **2.3e46 PB**。这是"超越验证器规模仍能编译 + 安全认证"的直接证据，且耗时只随门数近似线性增长、与宽度无关。
2. **h=0（下游无 H）近乎全绿**：one-shot 100% 安全，省 406–660 T；greedy 省 793–922 T（≈ 全精确基线的 43%）。宽度 24→100 不改变正确性，只增加耗时。
3. **h≥0.1 时 one-shot 原始掩码 100% 非法**：它"省"221–724 T 全是假象（掩码本身不安全）；Tracker 修复必须丢弃 11–34 个块，仅剩 14–26 T。`Tracker Greedy` 略好（21–33 T）且同样廉价。
4. **H 断崖在尺度上依旧**：安全余量从 h=0 的 ~43% 基线塌到 h≥0.1 的 ~1%。瓶颈是 Hadamard，不是宽度、也不是验证器——与 §5.3 完全一致。
5. **Depth-Cap 在深电路上退化为 top-1**（`depth_budget(blocks≥16)=1`），故只省 ~21 T（h=0）/ 0 T（h>0），是四者里最差的。

### 7.5 诚实边界

- 这里的"安全"是 tracker 的**充分**判据（对角修正），**不是**精确判据；在这些宽度上无法与 oracle 对比（正因为 OOM），所以表里所有 T 节省都是**下界**。
- 本轮只回答"能否在超宽下安全编译并量化收益"，**不**证明 one-shot 本身变好——恰恰相反，raw one-shot 在此尺度上 100% 非法。
- 顺带修掉一个潜在 bug：`WideInstance` 在 `ancilla_pool < n-2` 时会静默漏映射一根导线（`KeyError`）；已加 `n ≤ ancilla_pool + 2` 的钳制。

## 8. 消融：贪心排序与验证预算（NN 到底赢在哪）

> 数据源 `reports/figure_data/ablation_ordering.json`（`ablation_ordering.py` 直接落盘）。
> 复现：`.venv/bin/python ablation_ordering.py --a1-circuits 500 --deep-circuits 20 --wide-circuits 20`

贪心解码器 `for b in ORDER: if safe(accepted|{b}): accepted|={b}` 的结果**完全由排序决定**。这里把"冻结策略排序"与三种**零成本**静态规则对比：

| 排序 | 含义 | 成本 |
|---|---|---|
| `policy` | 模型打分降序 | 一次前向 |
| `reverse_index` | `idx=K-1…0`（末端优先） | 免费 |
| `saving_desc` | 单块可省 T 降序（并列时从后往前） | 免费 |
| `random` | 随机打乱（5 次平均） | 免费 |

### 8.1 架构事实与被测模型的边界（诚实归因）

本节（以及 §5、§7、§8 的全部结论）测的都是 `BlockVariantPolicy`
（[train_variant_policy.py](../train_variant_policy.py)、`checkpoints/variant_policy_rl_best.pt`），
**不是**本仓早期那条自回归相位多项式主线 `PhaseGadgetGNN`
（[Linux-MCX](../Linux-MCX)：**1,954,950 ≈ 1.95 M 参数**，`hidden=512`、`max_phase_terms=256`、`max_qubits=16`）。
两者任务不同、权重不共享，**论文里不可混用**。

被测模型 `BlockVariantPolicy` 的客观事实：

| 项 | 事实 |
|---|---|
| 参数量 | **24,915**（106 KB checkpoint）；`hidden=64`、`node_dim=27`、`context_dim=34` |
| 结构 | `GINEConv(27→64)` → `GCNConv(64→64)` → `global_mean_pool` → 拼接 `context_mlp(34→64→64)` → `MLP(128→64→1)` |
| 图输入 | `_block_graph(n)` **按控制数缓存**（`_BLOCK_GRAPH_CACHE`）：控制数相同的块拿到**逐字节相同**的图 |
| 推论 | 池化后的图嵌入是**只依赖控制数 n 的常数向量**；图卷积分支只是一个"控制数基元先验"，**完全不区分不同的块** |
| 真正的判别信号 | **全部**来自 34 维宏观上下文：下游 H 统计（`h_next` / `h_down` / `h_layers` / `h_max`）、块位置（`block_index` / `position` / `remaining`）、`num_controls` 与 `blocks` 的 one-hot、`t_exact` / `t_relative` |
| 训练 | 先监督 BCE（标签 = 该块是否属于穷举 oracle 掩码），再用 REINFORCE 微调 |
| "RL" 的性质 | 每块**独立**采一个 Bernoulli 位，动作之间**没有状态转移** → 这是**上下文赌博机（contextual bandit）**，不是 MDP/序贯 RL；`reward = 合法余量归一化节省 − risk_penalty·(不安全)` |
| 观察到正增益的唯一配置 | **精确验证器 + 受限查询预算 B ≪ k**（这是"已测配置中的观察"，**不是**对模型能力边界的断言）；无预算时增益 **0.00 T**（§8.2），换 Tracker 后**输给零成本的 `reverse_index`**（§8.3） |

**一个必须排除的替代解释**：§8.3 中"换 Tracker 后输 21–36 T"**不能**直接读成"学习无用"——它同时混杂了
(a) **判据不匹配**（模型在*精确 oracle* 标签上训练，却拿到 *Tracker* 判据下评测）与
(b) **分数贪心 + 非单调安全性的搜索缺陷**。要坐实"学习无用"，必须补做 §8.6 的 oracle 对照（见下）。

**归因结论（写论文时必须照此表述）**：本节的增益**不能**写成"GNN 从 ZX 图里学到了跨块相干结构"——
图输入是常量，跨块相干安全性的判别**全部**由手工上下文特征 + bandit 微调承担。
若保留该模型，应称为 **"context-feature 排序器（带控制数先验的图分支）"**，而不是 "graph neural network"。
换更一般的数据分布（控制数/块数/H 位置）时，本节的结论都需重测。

### 8.2 无预算：排序无关，NN 增益 = 0.00 T

| 场景 | policy | reverse_index | saving_desc | random | policy − 最佳静态 |
|---|---:|---:|---:|---:|---:|
| 精确验证器，500 条混合电路(5–12 块) | 33.70 | 33.70 | 33.70 | 33.70 | **+0.00** |
| 精确验证器，20 条深电路(30–50 块) | 24.60 | 24.60 | 24.60 | 24.60 | **+0.00** |
| Tracker，24q 深电路(h=0.1) | 35.55 | 35.55 | 35.55 | 35.55 | **+0.00** |
| Tracker，50q 深电路(h=0.5) | 21.15 | 21.15 | 21.15 | 21.15 | **+0.00** |

**掩码级复核**：500 条精确电路里，四种排序的贪心掩码 **499/500 完全相同**；唯一不同的一条（控制数 `[2,3,3,4,2]`）两个掩码的省 T **仍然相等**（差异块控制数相同）。

**结论**：验证预算充足时，神经网络排序相对零成本启发式的增益是 **0.00 T**。§5.2 里贪心距 oracle 的那 3.6% **不是排序问题**，而是"贪心只给极大解、不给最大解"的结构性缺口（beam/1-swap 也修不掉，见 §5.2）。

### 8.3 受限查询预算：排序才起作用，胜负随 oracle 翻转

预算 `B` = 每条电路最多调用验证器/Tracker B 次（只测排序最前的 B 个块）。

**精确验证器 —— NN 在这里真正胜出：**

| 场景 | B | policy | reverse_index | saving_desc | random | policy − 最佳静态 |
|---|---:|---:|---:|---:|---:|---:|
| A1 500 条(5–12 块) | 1 | 13.33 | 15.02 | 9.31 | 4.27 | −1.69 |
| A1 | 3 | 31.00 | 16.53 | 19.57 | 13.24 | **+11.42** |
| A1 | 5 | 32.30 | 19.35 | 27.15 | 21.80 | **+5.15** |
| A1 | 10 | 33.66 | 30.20 | 33.47 | 32.63 | +0.19 |
| A2 20 条(30–50 块) | 1 | 10.80 | 11.10 | 6.75 | 1.02 | −0.30 |
| A2 | 3 | 19.05 | 11.85 | 6.75 | 1.74 | **+7.20** |
| A2 | 5 | 24.45 | 11.85 | 6.75 | 2.88 | **+12.60** |
| A2 | 10 | 24.60 | 11.85 | 9.15 | 6.87 | **+12.75** |

**Tracker（宽寄存器）——NN 大输给零成本规则：**

| 场景 | B | policy | reverse_index | saving_desc | random | policy − 最佳静态 |
|---|---:|---:|---:|---:|---:|---:|
| 24q h=0.1 | 1 | 0.00 | 21.60 | 9.75 | 1.08 | **−21.60** |
| 24q h=0.1 | 5 | 0.00 | 35.55 | 16.65 | 5.40 | **−35.55** |
| 50q h=0.1 | 5 | 0.00 | 28.05 | 11.40 | 3.87 | **−28.05** |
| 50q h=0.5 | 5 | 0.00 | 21.15 | 9.45 | 2.58 | **−21.15** |
| 50q h=0.5 | 10 | 0.00 | 21.15 | 12.75 | 6.48 | **−21.15** |

### 8.4 为什么会翻转（关键解释）

1. **Tracker 的判据有乘积结构。** 它的规则（H 命中即"broken"、CNOT/块只做**并集**式支撑传播）意味着
   `safe(S) = ∧_{i∈S} survives(i)`，且 `survives(i)` 与掩码无关。于是：**无预算时任何顺序的贪心都收敛到同一个最大可行集 F**（也就是 Tracker 下的最优），排序完全无关；而**最后一个区块永远安全**（下游无 H），所以 `B=1` 时 `reverse_index` 直接拿走它的完整节省。**这条准则下，模型没有任何可做的。**
2. **模型是拿精确 oracle 的标签训的**（预测"该块是否属于精确最优掩码"），与 Tracker 的准则**不一致**。所以在 Tracker 下，模型把那些"精确可行但 Tracker 不可行"的块排到前面，B 很小时预算被全部浪费 → **0.00 T**。
3. **精确验证器是唯一让"学出来的排序"有价值的场景**：它的可行集非单调、且块间存在价值差异（控制数决定省 T），模型确实学到了一点"既可能安全、又值钱"的联合信息，故在 B=3–10 稳定胜出。

### 8.5 直接回答"NN 到底赢在哪"

- **唯一干净胜场**：**精确验证器 + 受限查询预算 B ∈ {3,5,10}**，比最强零成本静态规则多省 **5–13 T**（A1 `+5.2…+11.4`，A2 `+7.2…+12.8`）；B=1 时反而略输。
- **无预算**：**不赢**（0.00 T）——排序根本不影响结果。
- **换成 Tracker**：**惨败**（−10…−36 T）。部署 Tracker 时应**直接丢弃模型排序**，用 `reverse_index`，或干脆用一次 O(k·gates) 前向扫描直接算出可行集 F（**零次模型调用**即得 Tracker 下的最优）。

### 8.6 待做的判定性实验：与穷举 oracle 的最优性缺口

在可穷举的规模（≤ 20 块）上，比较四种解码器相对**精确最优**（2^k 穷举，已有现成 oracle）的缺口：
① 模型排序 ② `reverse_index` ③ 按 ΔT 降序贪心 ④ 精确最优。

- 若**精确最优显著优于所有贪心** → 真实结论不是"ML 无用"，而是"**所有贪心都差，可以用代数/ILP 精确求解**"——
  这会把论文从工具报告抬成**方法论文**，且数据现成、成本最低。
- 若精确最优 ≈ 所有贪心 → 才可以说"该问题上启发式已足够，学习无边际价值"。

**在这个实验做完之前，不要在任何地方写"学习无用"。**

## 10. 局限与后续

1. **§4 的深度条件化上限仍未达到"既要又要"**（深电路省 T 比"阈值+修复"低 37%）。要再进一步，需要把上限做成**可学的序贯决策**（例如按置信度顺序逐个决定、每步看已提交状态），而不是预先固定的 top-k；但那本质上就是在逼近贪心。
2. **贪心不是严格最优（§5.2）**：500 条随机电路上聚合捕获 **98.4%**、逐点 **96.4%**，最差一条短 60 T。根因是安全约束**非单调**，"拒绝即不回看"的贪心存在结构性缺口；已实测的 multipass / 1-swap / beam 都补不上。要 100% 需 2^k 穷举（k ≲ 20 可行，更大的 k 不可行）——这是当前部署与理论上限之间唯一已知的、无法用同族启发式消除的差距。
3. 目前所有安全判据都是**全局测量统计**一致；未考虑噪声/近似保真度预算。
4. **T-depth / t-par 尚未覆盖**：§6 只做了 T-count；t-par 基线需要一个独立实现（见 §6.4 第 1 条）。
5. **"宽度"有两种含义，别混用**：在共享寄存器框架（`mixed_stress`）里所有块共用 `n_max+1` 个数据比特，验证器成本是 `2^(n_max+1)`（`n_max` = 最大控制数），舒适到 `n_max` ≈ 18；而在**真正宽寄存器**的电路里（§7，块落在不同导线上），成本是 `2^N`，12–19 比特以上就 **OOM**。
6. **最有潜力的"做大蛋糕"方向不是 ML 而是编译期 H 重排**：h_prob=0 时可拿到 100% 的合法上界（952 T），说明只要把 Hadamard 从目标区块的下游挪开，降级就能活。这需要 Clifford 重综合/对易来腾出 H-free 窗口。
7. **超宽实测只给下界（§7）**：24–100 比特上精确判据不存在（OOM），安全性只能由 `support_tracker` 的充分判据认证，故报告的 T 节省是**下界**；且 raw one-shot 在此尺度 100% 非法，收益全部来自 Tracker 修复/贪心。
8. **排序消融的边界（§8）**："无预算时排序无关"是**实测**结论（精确验证器 499/500 掩码相同、Tracker 侧有乘积结构支撑），并非对任意电路族的一般定理；受限预算下的胜负也只在这三类实例上测过，换分布（控制数/块数/H 位置）需重测。
